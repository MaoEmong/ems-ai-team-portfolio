# ADR 0200: 프론트엔드 스택과 상태 관리

- 날짜: 2026-10-16
- 상태: 채택
- 결정 주체: 스택은 사용자 승인 작업안, 세부 구현 선택은 Codex

## 맥락과 결정

MVP는 관리자 사원·조직 CRUD와 일반 사원 본인 조회를 제공한다. 확정된 React·TypeScript·Vite를 사용하고 React Router로 URL과 역할 가드를 구성한다. TypeScript strict 모드를 켠다.

인증은 Context, 각 폼과 목록 필터는 컴포넌트 상태, API 조회는 공통 `useResource` 훅으로 관리한다. 조회 경로 변경 시 이전 응답이 최신 결과를 덮어쓰지 않도록 effect 정리에서 응답 적용을 취소한다. 변경 요청 후 재조회하며 전역 서버 캐시는 도입하지 않는다. 요청의 401·403·오류 객체 처리는 API 클라이언트에 모은다.

목업은 fetch 호환 메모리 어댑터를 환경변수로 선택한다. 서비스 워커 설치 없이 같은 API 경로·요청·응답·권한·충돌 응답을 검증할 수 있어 현재 범위에 채택했다. MSW 도입은 필수가 아닌 제안이므로 채택하지 않았다. 테스트는 Vitest + Testing Library로 사용자 동작과 결과를 확인한다.

## 대안과 영향

Redux나 서버 캐시 라이브러리는 현재 규모에서 상태 동기화 요구보다 설정 비용이 크다고 AI가 판단해 보류했다. 화면 간 캐시·중복 요청·낙관적 변경 요구가 커지면 재검토한다. 단순 훅은 재시도 버튼을 제공하되 자동 재시도나 캐싱은 하지 않는다.

목업은 메모리 기반이므로 새로고침 시 초기화되며 서버/DB 통합 검증을 대체하지 않는다. 실제 API와 차이가 생기면 계약 변경은 프로젝트 검토 기록에 확인하고 목업을 갱신한다. React의 기본 텍스트 escaping을 사용하고 서버 문자열을 HTML로 삽입하지 않는다.

## 검증 근거

핵심 폼·인증·역할 및 사원/부서 CRUD 흐름 테스트, 타입 검사와 빌드 결과는 [개발일지](../devlog/20261016-frontend-mvp.md)에 기록한다. 개발 도구 Codex와 제품 LLM(향후 Claude API/Ollama)은 별개이며 이 MVP에는 제품 LLM 호출이 없다.
