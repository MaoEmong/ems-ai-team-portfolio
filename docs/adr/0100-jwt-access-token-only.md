# ADR 0100: JWT Access token만 사용하는 MVP 인증

- 상태: 채택
- 날짜: 2026-10-16
- 결정 주체: 설계 검토 킥오프 결정. 구현과 아래 기술적 해석은 백엔드 Codex.
- 범위: MVP, 외부 배포 없음.

## 배경과 결정
JWT Access token의 유효기간은 3600초이며 refresh token은 제공하지 않는다. 프론트는 sessionStorage에 저장하고 401이면 로그인 화면으로 이동한다. 로그아웃은 클라이언트에서 토큰을 삭제한다.

Spring Security Resource Server와 Nimbus로 HS256 서명·검증한다. JWT_SECRET은 최소 UTF-8 32바이트이며 저장소에 넣지 않는다. 토큰 subject는 사원 ID, issuer는 ems, 만료 검증의 clock skew는 0초다. 로그인 비밀번호는 BCrypt 해시로 저장한다.

매 인증 요청에서 DB 계정의 enabled와 현재 role을 조회한다. 퇴사자의 기존 토큰은 즉시 이후 요청에서 401이며, 권한 변경도 이전 토큰에 반영된다. 사원 상세 권한은 ADMIN 또는 본인이다. 인증된 일반 사원도 부서·직급 목록을 조회할 수 있다는 설계 검토 답변을 적용했다.

## 판단과 대안
Refresh token 회전·재사용 탐지를 MVP에 추가하는 복잡도를 피하고 명시된 1시간 재로그인 방식을 채택했다. 서버 세션으로의 변경은 확정 JWT 계약과 다르므로 채택하지 않았다. 권한 클레임만 신뢰하는 방식은 퇴사 계정 차단 요구를 만족하지 못하므로 기각했다.

## 한계
로그아웃으로 이미 탈취된 토큰까지 서버에서 무효화하지는 않는다. sessionStorage는 자바스크립트 접근이 가능해 XSS에 취약하므로 토큰을 로그나 HTML에 노출하지 않아야 한다. DB 조회를 하므로 완전한 무상태 인증이 아니며 계정 조회 비용이 있다. 단일 대칭키 회전 시 기존 토큰은 무효화된다. 향후 운영 배포 단계에서 쿠키·CSRF, 키 회전, refresh 또는 서버 세션을 다시 평가한다.

## 검증
컨트롤러 테스트: 미인증 401, EMPLOYEE 변경/목록 권한 거부, CORS.
MySQL 통합 테스트: 로그인, 본인/타인 조회, 퇴사 전 발급 JWT의 퇴사 후 401.
실행 결과는 개발일지를 참조한다.
