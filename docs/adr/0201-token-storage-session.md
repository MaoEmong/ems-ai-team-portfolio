# ADR 0201: sessionStorage Access token 보관

- 날짜: 2026-10-16
- 상태: 킥오프 결정 적용
- 결정 근거: 확정 MVP 인증 계약

## 결정

Access token 하나를 sessionStorage의 `ems.accessToken` 키에 보관한다. API 요청 시 `Authorization: Bearer` 헤더에 첨부한다. 시작 시 `/auth/me`로 사용자 정보를 조회하며 역할은 해당 응답을 사용한다. 만료 1시간, refresh 없음은 서버 계약이다.

401을 받으면 공통 클라이언트가 토큰을 삭제하고 인증 상태를 초기화한다. 보호 라우트는 로그인 화면으로 이동한다. 로그인 요청 자체가 401인 경우에는 입력 오류 안내를 표시한다. 네트워크 오류나 서버 5xx만으로 토큰을 삭제하지 않으며 재시도를 제공한다. 403은 권한 없음 안내로 구분한다. 로그아웃은 클라이언트 토큰 삭제다.

## 근거와 한계

브라우저 탭 세션에 보관해 localStorage의 장기 잔존을 피하면서 새로고침 후 인증 확인이 가능하다. 그러나 sessionStorage도 JavaScript에서 읽을 수 있어 XSS 발생 시 탈취될 수 있다. 이 결정은 XSS 방어를 대체하지 않는다. 토큰을 URL·로그·개발일지에 기록하지 않고 서버 응답을 HTML로 직접 렌더링하지 않는다.

클라이언트 로그아웃만으로 발급된 토큰을 서버에서 폐기하지 못한다. 퇴사자의 계정 비활성화와 기존 토큰 차단은 서버가 매 요청 수행한다. HttpOnly 쿠키와 refresh token 회전은 MVP 계약에 없으므로 임의 도입하지 않았다. 향후 인증 요구 변경 시 CSRF·CORS와 함께 별도 검토한다.

메뉴/라우트 가드는 사용자 경험을 위한 것이며 서버의 역할/본인 권한 검증을 대체하지 않는다. 일반 사원은 관리자 화면과 수정 동작을 사용할 수 없다. 테스트에서 401 토큰 삭제·로그인 전환, 역할별 화면 및 서버 403 안내를 검증한다.
