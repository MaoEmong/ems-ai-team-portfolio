# ADR 0103: 발령 전용 조직 변경과 PUT 호환
- 상태: 채택, 2026-10-16
- 근거: 2단계 회의 결정 및 설계 검토 .
## 결정
사원 생성은 부서·직급을 필수로 지정한다. 수정 PUT은 departmentId/positionId를 선택 입력으로 받고 생략/null/동일 값은 유지, 다른 값은409 APPOINTMENT_REQUIRED로 거절한다. 기존 클라이언트의 동일값 전송과 새 프론트의 필드 생략을 모두 지원한다.
발령은 사원 행 잠금 후 최신 소속을 읽고 현재 소속 갱신·이력·감사를 같은 트랜잭션으로 저장한다. 유효일은 입사일/마지막 발령일 이상, 서울 오늘 이하이며 같은 날짜는 id순이다. 변경 없는 발령·사유 누락은400, 퇴사자는409다. 이력이 있으면 입사일을 최초 발령일 뒤로, 퇴사일을 마지막 발령일 앞으로 바꿀 수 없다.
부서·직급 ID 및 당시 이름/level, 등록자 이름을 스냅샷으로 남긴다. 발령이 참조하는 부서·직급 삭제는 IN_USE409로 거절한다. V1은 보존하고 V2로 추가한다.
## 판단과 한계
PUT 필드 완전 삭제 대신 선택 필드로 두는 백엔드 절충안을 설계 검토에서 승인했다. UI만 읽기 전용으로 만드는 방안은 우회 가능하므로 서버 검증한다. 오래된 화면의 요청을 자동 거절하는 버전 비교와 미래 예약 실행은 이번 범위에서 제외한다. 과거 발령을 추측해 만들지 않는다.
## 검증
MySQL에서 소속·발령·감사 원자성, 감사 저장 후 강제 실패 시 모두 롤백, PUT 호환/우회, 날짜와 권한, 이력 참조 삭제를 검증한다. 결과는 phase2 개발일지에 기록한다.
