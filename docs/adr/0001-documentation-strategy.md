# 0001. 기능·의사결정·검증을 연결하는 문서화

- 날짜: 2026-10-16
- 상태: 채택
- 근거: 사용자의 진행 중 문서 작성 요청 및 킥오프 설계 검토 결정.

## 배경

EMS는 기능 구현뿐 아니라 AI를 활용한 개발 과정이 핵심인 포트폴리오입니다. 최종 코드만으로는 역할 분담과 검토·수정 과정을 확인하기 어렵습니다.

## 고려한 대안

1. 완료 후 README만 작성: 초기 판단과 실패·수정 증거가 유실될 수 있습니다.
2. 대화 전체 복사: 읽기 어렵고 비밀값·중복 정보가 섞일 수 있습니다.
3. 요구사항·계약·ADR·일지·회의록을 작업 중 연결: 관리 비용이 있으나 실제 판단과 검증을 추적할 수 있습니다.

## 결정과 근거

3안을 채택합니다. 요구사항에 기능 ID와 인수 조건을 부여하고, 아키텍처·상세 API·ADR·일지를 연결합니다. 문서QA가 공통 문서와 색인을 관리하고 각 팀이 고유 일지와 대역별 ADR을 작성합니다. 계약 변경은 설계 검토을 통해 조율합니다.

## 결과와 한계

AI 제안과 채택 이유, 실제 실행 결과를 구분해 보여줄 수 있습니다. 문서와 코드가 달라질 위험은 단계 종료 검수로 점검합니다. 기록만으로 기능 동작을 증명할 수 없으므로 테스트와 실제 API·웹 검수를 별도로 수행합니다. AI 판단을 사람 판단으로 표현하지 않습니다.
