# ADR 0206: AI 명시 실행과 화면 수명에 한정한 결과

- 상태: 채택, 구현·자동 검증·Claude 최종 이미지 확인 완료
- 결정 주체: 7단계 정책은 Claude Code(설계 검토), 프론트 구현 선택은 프론트 담당(Codex)
- 기준: phase4-ai-api.md v1.0, SHA-256 `E117946FE967747697A8AD6A3D0AF9A729991DB1A547BB6A468D7B09601A5617`

## 문제

자연어 필터 제안은 기존 검색 조건과 다를 수 있고, 생성 요약은 확정 평가의 원문이나 점수와 동일한 권위를 갖지 않는다. 늦게 도착한 응답이 새 요청이나 다른 계정의 화면에 섞이는 것도 막아야 한다.

## 결정

실행 전 `/ai/config`를 조회하여 실제 제공자 설정, Mock 여부, 외부 전송 필드를 표시한다. 설정 조회만으로 생성 POST를 호출하지 않는다. 사용자의 명시 실행만 POST를 만들며 자동 재시도와 공유 결과 캐시는 두지 않는다. Mock에는 실제 추론이 아니라는 문구를 표시한다. Ollama도 EMS 프로세스 밖으로 전송하므로 외부 전송 고지를 적용한다.

검색 결과는 서버가 검증한 다섯 필드(keyword, departmentId, positionId, status, sort)의 제안이다. OK 상태에서만 적용 버튼을 제공하고 사용자의 적용이 기존 목록 조회를 발생시킨다. 생략된 조건은 적용하지 않으며 직책과 입사일 범위는 지원하지 않는다.

설계 검토 결정 에 따라 제안을 질문의 전체 검색 조건으로 취급한다. 적용 전 현재→적용 후 비교표를 보여 주고 명시 확인한 뒤 다섯 필드를 전체 교체한다. 생략된 keyword/departmentId/positionId/status는 빈 값(기존 퇴사 제외 기본), sort는 employeeNo,asc로 돌아간다. 기존 page/size는 AI 제안에서 받지 않는다. 적용 후 기존 수동 필터는 계속 수정할 수 있다. 규정 메뉴는 내 업무, requestId는 결과 메타데이터에 표시하며 retryable 없는500에는 별도 다시 실행 버튼을 만들지 않는다. 요구사항 AI 번호 대응표는 문서QA 소유다.

평가 요약은 FINALIZED 상세에만 연결하고 평가 ID만 전송한다. 서버가 권한과 코멘트를 다시 조회한다. 읽기 전용 결과를 원문·점수·등급과 분리하며 저장·제출·적용 경로를 만들지 않는다. 규정 Q&A는 인용의 문서 ID/버전/절/발췌를 텍스트로 표시하고 임의 URL을 링크로 변환하지 않는다. 인용 검증이 의미 정확성을 보장한다고 표현하지 않는다.

입력과 응답은 컴포넌트 메모리에만 보유한다. 저장소·URL·콘솔에 원문을 넣지 않는다. 취소·화면 해제·계정 변경 시 요청을 중단하고 이전 응답을 폐기한다. 브라우저 중단이 제공자의 처리나 비용 취소를 보장한다고 안내하지 않는다. 오류의 retryable은 나중에 사용자가 다시 시도할 수 있다는 뜻이며 자동 호출 조건이 아니다.

## 검증과 한계

단위 테스트·목업 Chromium·Claude 이미지 검수의 최종 결과는 개발일지에 실행 후 기록한다. 기존 수치를 이월하지 않는다. 제품 제공자의 실제 호출과 실제 Compose 검수는 목업 검증과 별개의 증거이며 프론트에서 미실행이다.

실제 평가 조회 bridge는404만null로 취급한다. 응답없음·기타 실패상태·JSON 파싱 오류는throw하여 목업 AI factory가 안전한500으로 처리한다. 독립6개 테스트로 이 경계를 고정했다. mock-phase4의70개와 ai화면33개는 Codex 구현 담당이 작성하고 자체 실행 없이 소유권을 반환했으며 담당이 전체 검증했다.

Claude 이미지 검수에서 AI 요약이 원문보다 앞에 나오는 문제를 발견해, 원문·최종 평균·등급 뒤의 별도 구분선/h2 구역으로 옮겼다. 반복 제목·모바일 비교 정렬·일부 중복 안내는 낮음 수용 결정과 잔여 위험을 디자인 검수 문서에 남긴다. 개발 엔진 우열이나 실제 추론 품질을 이 검수 결과로 주장하지 않는다.

개발 역할은 Claude 시안·이미지 검수, Codex 구현·테스트다. 제품 제공자 Mock/Anthropic/Ollama와 구분한다. API 키나 제공자 URL은 프론트 설정으로 받지 않는다.
