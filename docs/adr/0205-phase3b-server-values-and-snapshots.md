# ADR 0205: 3B 서버 값과 스냅샷 표시

- 상태: 채택, 프론트 목업 검증·Claude 이미지 검수 완료
- 날짜: 2026-10-16
- 결정자: Codex 담당(설계 검토 3B 계약의 구현 선택)

## 맥락

조직도·직책, 데모 급여, 평가를 기존 EMS에 추가한다. 계약 버전은 설계 검토 공유와 해시로 식별한다. 급여·평가의 계산과 공개 시점은 서버 정책이며 화면의 버튼 숨김이 서버 인가나 원자성 검증을 대신하지 않는다.

## 결정

3B 기능은 조직도, 급여, 평가 모듈로 분리하고 기존 request/send·오류·확인 대화상자를 재사용한다. 조직도는 GET /organization의 평탄 departments/employees 배열에서 parentId로 화면 계층을 조립한다. 이는 허용된 표시 변환이며 사원 과거 소속이나 집계 값을 추정하지 않는다. 직급 Position과 직책 JobTitle은 별개다. 직책 지정·변경·해제는 changeJobTitle/jobTitleId를 명시하는 발령 경로만 사용한다. 기존 등록·엑셀 양식은 유지한다.

급여는 정수 원 값을 형식화해서 표시하며 grossPay/deductions/totalDeductions/netPay를 재계산하지 않는다. '포트폴리오용 데모 급여 — 실제 세법·4대보험 산정 아님'을 표시하고 파일 다운로드를 추가하지 않는다. 생성·재계산 시점 스냅샷임을 명시하고 과거 이력을 복원했다고 표현하지 않는다.

급여 월·평가 주기/평가서의 서버 allowedActions만 처리 버튼으로 사용한다. 재계산·확정·제출·재배정의 확인 대화상자에서 비가역성과 스냅샷 또는 초안 초기화 영향을 설명한다. 409 후 관련 목록·상세를 재조회한다. 평가의 관리자 답변·최종점수·등급은 응답에 키가 있을 때만 표시하며 본인 미확정 응답에서 추정·계산·복원하지 않는다. 코멘트는 React 텍스트로 표시한다.

## 분담과 검증

Claude가 시안·실제 이미지 검수/재확인, Codex가 조직/직책 연계·급여/평가 화면·목업·테스트·촬영을 맡았다. 작업 파일 소유권을 나누고 담당만 실행 검증했다. 실제 서버 E2E/DB 정합성은 문서QA·백엔드 증거와 구분한다.

담당은 다음과 같이 구분한다: Codex 담당은 공통 타입·라우팅·조직도·직책 연계·검사 실행·증거 통합, 기존 Codex 목업담당은 계약 목업과 목업 테스트, 새 Codex 업무화면담당은 급여·평가 화면과 화면 테스트, Claude UIUX디자이너는 시안·실제 이미지 검수·재확인이다. 엔진 우열이나 측정하지 않은 효과를 단정하지 않는다.

확정 계약은 v1.1(설계 검토 공유 저장 시각16:45:06), SHA-256 `9A56EAD34B8E4B8134FBD3A8E92B4D0F3FCFAFAF22495EC0D5ACB20AA6F0B3B2`이다. 주기 상세 조회의 assignments는 참조형 요약이며, 입력은 여전히 employeeId/reviewerId 쌍이다. 조회 DTO와 입력 DTO를 구분하고 편집 시 명시적으로 변환한다. 관리 요약이 민감 평가 상세 권한을 확대하지 않는다.

목업 브라우저는5174로 실제 Compose5173과 분리한다. Vitest는 VITE_MOCK_API=false를 고정해 브라우저용 로컬 환경값이 fetch 제어 테스트를 우회하지 않게 한다. 프론트팀은 실제 Compose를 사용하지 않으며 실제 서버 E2E는 미실행으로 분리한다.

## 실행 결과와 한계

2026-10-16 17:52:05 KST 최종 `npm test` 단일 실행166/166(10파일·기존97개 포함),17:52~17:53 타입 검사·빌드·5174 Chromium8/8(29.3초)을 통과했다. 기존 ExcelJS 큰 청크 경고는 남는다. Claude 검수는 3차에서 높음·중간 잔여0으로 판정했고,63장 중 최종 범위22장을 직접 확인하고41장은 2차 판정을 유지했다. 최종 EOF 공백 정리 후 다시 검증·촬영한63장의 SHA-256이 검수본과 모두 같음을 확인했다. 실행·해시 증거는 frontend/design-evidence/phase3b/verification.json, ID별 판단은 docs/design/design-review-phase3b.md에 있다.

급여 설정과 평가의 사원 식별은 기존 GET /employees/{id}만 쓴다(payroll.tsx SalarySettings, evaluations.tsx PersonIdField). 별도 후보 API를 만들거나 클라이언트에서 평가자 자격을 최종 판정하지 않는다. ID를 알아야 하는 불편, 월 상세 머리의 배지 차이, 사이드바 스크롤 제목 잘림은 Claude가 근거·잔여 위험과 함께 수용했다.

검증 작업 큐가 대기 구현 담당에게 전달되지 않아 설계 검토 결정으로 급여·평가3파일 소유권을 담당에게 이전했다. 디자인 지적 반영과 최종 실행은 Codex 담당이 직접 했으며 새 Codex 화면 담당이 그 수정을 한 것으로 쓰지 않는다. 메시지 원문 전달 누락은 임시 파일 인계로 대응했고, 최종 문서에 사실을 옮긴 뒤 임시파일3개를 삭제했다.

실측 대비·스크린리더·실제 API 화면·태블릿/확대는 미확인이다. 메모리 목업은 실제 DB 잠금·트랜잭션·영속성·MySQL collation 증거를 대신하지 않는다. 실제 백엔드 E2E는 미실행이며 문서QA가 맡는다.
