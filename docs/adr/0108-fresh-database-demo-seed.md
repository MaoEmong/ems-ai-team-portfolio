# ADR 0108: 새 DB 데모 시드 분리
상태: 채택, 기존 V2 볼륨 및 새 빈 DB 검증 완료.
V1/V2 SQL을 유지하고 V3에 demo_seed_marker를 추가했다. ApplicationRunner의 동일 트랜잭션에서 marker id=1 INSERT IGNORE가 성공하고 employee.count=0일 때만 시드를 생성한다. 마커 유일키가 동시 시작을 직렬화한다. 실패하면 마커·데이터가 함께 롤백한다.
마커 또는 사원이 이미 있으면 시드를 적용하지 않는다. 기존 DB에는 보호용 마커만 남기며 사원·계정·입퇴사일·발령·감사는 덮어쓰지 않는다. 마커가 남은 DB의 사원을 임의 삭제해도 자동 재생성하지 않는다.
새 DB 총31명: 환경변수 초기ADMIN1명과 합성30명. DEMO001은 추가ADMIN이다. 선택 DEMO_ADMIN_INITIAL_PASSWORD는 새 시드 때만 사용하고, 미설정은 무작위 비밀번호다. 최근12개월 입사 분산과 일부1~3년 근속, 퇴사5명·계정 비활성화를 적용한다. 기본 목록은26명이다.
근태·휴가 표본 자동삽입은 선택 범위에서 제외하고 API로 생성한다. 현재시각·결재 주체·감사/알림 원자성을 실제 흐름으로 검증하기 위해서다.
Compose 검증(2026-10-16 13:38:36~13:41:58 KST): 유지 V2의 사원43/계정43/발령3/감사49를 V3 적용 직후 동일 행수와 CHECKSUM TABLE로 보존 확인했다. 새 DB31/31/퇴사5/기본HTTP목록26/DEMO001 ADMIN과 퇴사계정 비활성화를 확인했다. 실제 3A 흐름 후 백엔드 재시작에서도 사원·계정·발령·감사 체크섬과 수가 같았다. 두 환경 모두 down, 볼륨 유지.
