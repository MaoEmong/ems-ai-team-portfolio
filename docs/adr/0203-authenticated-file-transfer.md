# ADR 0203: 인증된 파일 입출력과 오류 처리

- 날짜: 2026-10-16
- 상태: 채택
- 근거: 2단계 확정 API 계약 및 계약 보충

## 결정

공통 requestResponse가 Authorization 및 401·403·JSON 오류를 처리한다. JSON 클라이언트는 이 함수를 재사용하고 파일 다운로드는 성공 Response에서 Blob을 만든다. Content-Disposition의 UTF-8 filename*를 우선 해석하고 경로 문자를 제거한다. 다운로드 링크를 실행한 뒤 object URL을 해제한다. UI의 완료 문구는 서버 파일 생성 성공을 의미하며 디스크 저장 완료를 보장하지 않는다.

내보내기는 클릭 시점의 keyword/departmentId/positionId/status/sort와 format만 전송한다. page/size는 전송하지 않는다. 10,000행 상한 오류는 일부 파일로 바꾸지 않고 표시한다. 가져오기는 multipart file을 전송하며 Content-Type 경계값은 브라우저가 만든다. 클라이언트는 확장자와 5MiB를 먼저 확인하고 서버가 시트·행·중복·수식·압축해제 제한을 최종 검증한다.

요청 중 ref 잠금과 disabled를 함께 사용해 중복 제출을 막는다. 가져오기 전 확인 대화상자를 제공한다. 서버 검증 실패는 전체 취소 안내와 실제 엑셀 rowErrors를 표시하고 IMPORT_CONFLICT는 행 번호를 만들어내지 않는다. 네트워크 단절은 서버 처리 결과가 불명확하므로 목록 확인을 안내한다. 초기 비밀번호·파일 입력 원문을 오류나 개발일지에 기록하지 않는다.

## 목업과 한계

목업 파일 호환을 위해 ExcelJS를 사용하고 필요 시 동적 로딩한다. 실제 API 모드의 브라우저는 서버 파일을 전달할 뿐 클라이언트에서 엑셀을 재생성하지 않는다. 목업은 UI·파일 흐름 검증용이며 JVM의 압축 폭탄 방어, 실제 JWT, MySQL 트랜잭션·경쟁 제약을 대체하지 않는다.

설치 감사에서 ExcelJS 전이 uuid 취약점이 발견되어 실제 사용이 v4 생성뿐임을 확인하고 ^11.1.1 override를 적용했다. npm 재설치 감사 0건을 확인했고 실제 xlsx 생성·읽기는 목업 테스트/브라우저 검증으로 호환성을 확인한다. 상세 실행 결과와 제한은 개발일지에 기록한다.
