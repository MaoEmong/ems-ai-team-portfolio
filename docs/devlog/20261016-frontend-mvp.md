# 2026-10-16 프론트엔드 MVP 개발일지

## 받은 지시

설계 검토 검증 작업: 킥오프 API 계약에 맞춰 React·TypeScript·Vite 프론트엔드 구현. 로그인, 사원 목록·상세·등록·수정·퇴사 처리, 부서·직급 CRUD, 일반 사원 내 정보, 인증·오류 처리, 목업 및 실제 API 전환, 테스트, Dockerfile·README, ADR 2건을 제공한다. backend·Compose·공통 문서는 수정하지 않고 Git 커밋은 하지 않는다.

## 수행 내용

- `frontend/`에 앱과 lockfile, 환경변수 예시, Dockerfile·nginx 설정·README를 작성했다.
- 사원 목록은 키워드/부서/직급/상태 AND 필터, 사번/이름/입사일 양방향 정렬, 페이지 크기 및 이동을 제공한다. 기본 목록은 퇴사자를 제외한다.
- 사원 등록·수정 폼은 필수값, 이메일, 문자열 상한, 비밀번호 UTF-8 72바이트 한도를 검증한다. 퇴사는 확인 대화상자와 날짜 입력으로 진행하며 `퇴사 처리` 명칭을 사용한다.
- 부서·직급은 목록·등록·수정·삭제 확인을 제공하고 참조 중인 항목의 409 사유를 표시한다.
- 인증 Context와 sessionStorage, Authorization 자동 첨부, 401 재로그인, 403 권한 안내, 서버 fieldErrors의 필드별 표시를 구현했다. 일반 사원은 내 정보만 사용하며 관리 라우트를 차단한다.
- 메모리 목업 어댑터는 합성 사원 31명, 관리자/일반 계정, 인증·역할·필터·페이지·수정·퇴사·중복/참조 충돌을 제공한다. 목업 세션도 퇴사 후 다음 요청에서 거절한다.
- 로딩·빈 상태·서버 오류·재시도, 모바일 대응, 대화상자 포커스 순환과 Escape 취소를 구현했다. 외부 폰트 다운로드 의존성을 제거했다.
- ADR 0200/0201에 스택·상태 관리와 토큰 저장 근거 및 한계를 기록했다.

## AI 제안 채택·수정·기각과 근거

- 스택·sessionStorage·권한·퇴사 정책은 사용자 승인 작업안과 설계 검토의 킥오프 결정을 적용했다. 이를 프론트 AI의 독자 결정이나 사람의 코드 검토로 표현하지 않는다.
- 프론트 Codex가 Context와 지역 상태, 공통 API/조회 훅을 제안하고 채택했다. MVP의 서버 캐시 요구가 작아 Redux 등의 별도 전역 상태 도입은 보류했다.
- MSW는 예시로 제시된 도구이므로 필수 의존성으로 해석하지 않았다. fetch와 같은 입력/Response를 사용하는 메모리 어댑터로 실제 UI와 테스트를 함께 검증한다. 서비스 워커 생성이 필요 없다는 장점과 새로고침 초기화·서버 검증 미대체 한계를 README에 명시했다.
- 백엔드 상세 API 문서가 생긴 뒤 대조했다. `User.id`가 사원 ID임을 확인해 내 정보 조회에 사용했다. 상세 문서의 설계 검토 승인 근거()가 명시된 `EMPLOYEE_RETIRED`와 퇴사자 수정 금지를 적용했다.
- 목업 단위 테스트만으로 완료 판단하지 않고 실제 Chromium의 목업 UI 검증을 추가했다. 이는 실제 백엔드 E2E와 구분한다.
- 개발 도구는 Codex이며 제품 LLM 공급자 Claude API/Ollama 호출은 이번 MVP 범위가 아니다. 구현 담당 역할 지정·작업 분담·Git 커밋은 하지 않았다.

## 문제와 해결

1. 초기 디렉터리와 파일 쓰기, npm 캐시, Vite 임시 디렉터리 및 빌드 출력에 샌드박스 권한 오류가 발생했다. 필요한 명령만 권한 승인을 요청하여 실행했다. 권한을 우회하거나 다른 팀 파일의 ACL을 변경하지 않았다. 검토 기록에 질문 으로 상황을 전달했다.
2. 첫 타입 검사에서 unknown 오류 상태를 JSX 조건으로 사용한 타입 오류 2건이 발생했다. 조회 훅의 오류 반환 타입을 정리해 해결했다.
3. 초기 테스트 도구 의존성 감사에서 취약점 3건이 발견되었다. Vite/Vitest/React 플러그인을 수정 버전으로 갱신하고 lockfile을 생성했다. 최종 설치 감사는 0건이다.
4. 대화상자 포커스 보완용 PowerShell 편집 명령에 문법 오류가 한 번 있었다. 수정 후 승인된 쓰기 명령으로 적용하고 빌드·테스트를 재실행했다.
5. 브라우저 테스트 첫 실행은 Chromium 버전 불일치(실행 파일 없음)로 시작 실패했다. `npx playwright install chromium` 승인 실행 후 브라우저 테스트 2개가 통과했다.

## 검증 기록

환경: Windows PowerShell, Node 24.14.1, npm 11.11.0. 작업 위치 `E:\portfolio\ems\frontend`.

| 명령/검증 | 결과 |
| --- | --- |
| `npm install` | 승인 실행 성공, lockfile 생성 |
| `npm run typecheck` | 통과 |
| `npm test` | 11개 통과; 최종 코드 재실행 7.69초 |
| `npm run build` | 통과; TypeScript 검사 후 Vite 정적 번들 생성 |
| npm 의존성 감사 | 마지막 설치 시 0 vulnerabilities |
| `npx playwright test` | Chromium 설치 후 **2개 통과**, 총 4.0초 |
| localhost:8080 TCP 확인 | 연결 실패. 실제 백엔드 연동 E2E **미실행** |
| Docker 이미지 빌드/Compose 실행 | **미실행**. 구성과 전달 요구사항만 작성 |

Vitest 검증 내용: 로그인·헤더, 401 토큰 삭제/로그인 이동, 로그인 실패, 일반 사원 내 정보, 관리자 URL 차단, 타인 정보 403, 폼 필수값/이메일/비밀번호, 빈 폼 저장 요청 차단, 사원 등록→수정→퇴사→퇴사 필터, 부서 CRUD/409, 서버 fieldErrors 표시.

실제 백엔드의 JWT·MySQL 통합 및 Docker 실행은 통과로 표시하지 않는다. 문서QA 통합 검수에서 실제 시드 계정과 서버를 준비해 확인해야 한다. Compose 파일은 수정하지 않았으며 프론트 서비스 설정은 `frontend/README.md`에 전달했다.

## 최종 확인

- Chromium에서 관리자 목록 20/11명 페이지 이동, 키워드 빈 결과, 부서 필터, 정렬 선택, 직급 등록·수정·삭제, 로그아웃을 검증했다. 일반 사원 본인 조회 및 관리자 URL 직접 접근 차단도 통과했다.
- 1280px 데스크톱과 390px 모바일 스크린샷을 직접 열어 확인했다. 모바일에서는 목록 표 내부가 가로 스크롤되고 페이지 전체 레이아웃은 화면 폭에 맞는다. 스크린샷은 로컬 `frontend/test-results/admin-desktop.png`, `admin-mobile.png`이며 Git 제외 산출물이다.
- Prettier로 소스·테스트·설정을 포맷해 검토 가능성을 높였다. 최종 설치 감사는 0건이다.
- 실제 API 포트는 완료 직전 재확인에서도 연결되지 않았다. 목업 브라우저 테스트를 실제 백엔드 E2E로 표시하지 않았다.
- 루트 Compose에는 아직 frontend 서비스가 없음을 읽기 확인했다. 검토 기록에 frontend README의 서비스 설정을 백엔드팀에 전달해 달라고 완료 보고한다.

## 후속: 설계 검토 계약 보충 검증

받은 지시: 인증된 EMPLOYEE의 부서·직급 GET 허용 및 변경 금지, 생성 201/수정·퇴사 200/삭제 204, 퇴사자 수정·중복 퇴사의 EMPLOYEE_RETIRED 409, 누락·입사일 이전 퇴사일의 fieldErrors를 확인한다.

수행 및 판단: 기존 목업과 화면을 읽어 세 항목이 모두 이미 구현되어 있음을 확인했다. 퇴사자의 수정·퇴사 버튼을 숨기고 수정 URL도 차단하며, 오류 안내는 409 사유와 retireDate 필드 오류를 표시한다. 동작 코드를 중복 변경하지 않고 계약 회귀 테스트 5개를 `frontend/src/mock-contract.test.ts`에 추가했다. 이는 AI의 검증 판단이며 사람의 코드 검토로 표현하지 않는다.

검증 결과: `npm run typecheck` 통과, `npm test` **2개 파일·16개 테스트 통과**(7.75초). 신규 테스트는 두 리소스의 EMPLOYEE 조회/변경 거부, 관리자 생성·수정·삭제 상태 코드와 응답 본문, 사원 생성·수정·퇴사 상태 코드, 잘못된 퇴사일의 400 fieldErrors, 퇴사 후 수정 및 중복 퇴사 409를 확인했다. 기존 화면 테스트도 함께 통과했다. 런타임 코드 변경이 없어 빌드와 브라우저 검증은 이번 후속에서 반복하지 않았다. 실제 백엔드 E2E 미실행 상태는 그대로다.
