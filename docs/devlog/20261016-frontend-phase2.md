# 2026-10-16 프론트엔드 2단계 개발일지

## 구현 기준

구현 범위: Claude Code 디자인 규칙·시안 → Codex 구현 → Claude Code 스크린샷 검수 → 반영 순서로 2단계 대시보드·발령·파일 입출력·감사 로그와 기존 화면을 정비한다. 계약은 회의록과 docs/api/phase2-api.md 및 검토 담당자 후속 확정이다. frontend, docs/design, 프론트 ADR0202/0203와 본 일지만 소유한다. backend/Compose/공통 문서/커밋은 금지다.

## 역할과 수행

- Claude Code 디자인 검토, 해당 작업: design-system.md, screens.md, mockups.html 작성 완료. 시스템 글꼴·접근성 토큰·SVG 제안·반응형·상태 문구를 설계했다. 구현 후 검수는 별도 진행 예정이다.
- Codex 프론트 통합 검증 담당자: 화면·라우터·파일 클라이언트·테스트·디자인 토큰·ADR 작성. 관리자 홈 대시보드, 발령 등록/이력, 수정 소속 읽기 전용·미전송, 가져오기 확인/행 오류, 현재 조건 내보내기, 감사 필터/안전한 전후값을 구현 중이다.
- Codex 목업 구현, 해당 작업: mock.ts, mock-phase2.ts, mock-phase2.test.ts만 맡겨 2단계 계약 목업과 xlsx 파일 호환을 구현한다. 빌드·테스트는 검증 담당자 단독 실행으로 지정했다.

## 판단 근거와 문제 해결

- 사용자가 요청한 역할별 엔진 배분을 실제 개발 엔진과 산출물에 연결했다. 디자인 원저자는 Claude Code, 구현 판단은 Codex이며 일반적인 엔진 우열을 주장하지 않는다.
- Claude Code의 디자인 토큰·시안과 인라인 SVG+수치 표를 채택했다. 서버가 반환하지 않는 월말 인원·과거 분포는 추정하지 않는다. 기존 16개 시나리오는 유지하되 관리자 첫 화면 변경에 따른 탐색 단계만 조정한다.
- 파일 공통 클라이언트는 JSON과 Blob 성공 응답을 분리하고 인증·오류 처리는 공유한다. FormData의 multipart 경계값은 브라우저가 설정한다. 내보내기는 허용 필터·정렬과 format만 전송하고 page/size를 제외한다.
- 업로드 API가 행 검증/충돌을 거절하면 전체 취소를 표시한다. 네트워크 단절은 서버가 이미 처리했을 수 있으므로 목록에서 결과 확인을 안내한다. 파일 이름과 실제 행 번호만 표시하며 비밀번호 입력 원문은 기록하지 않는다.
- 파일 편집 도구의 Windows 실행 인자 오류로 두 번 실패했다. 권한 승인된 PowerShell의 명시적 파일 쓰기로 변경했다. 임의 ACL 변경이나 담당 범위 밖 파일 편집은 하지 않았다.
- ExcelJS 설치 감사에서 uuid 전이 취약점 2건이 표시되었다. 실제 ExcelJS 사용은 v4 생성뿐임을 코드로 확인하고 uuid ^11.1.1 override를 적용했다. 재설치 감사는 0건이다. xlsx 호환성은 후속 테스트로 확인한다.

- npm install(override 적용): 성공, 감사 0 vulnerabilities.
- 추가 화면 테스트 및 Chromium 데스크톱/모바일 캡처 시나리오 작성. 2단계 목업 결과 취합 후 실행 예정이며 아직 통과로 표시하지 않는다.
- 실제 백엔드 E2E: 이번 프론트 작업에서는 미실행. 문서QA 통합 검수와 구분한다.
- Claude Code 구현 디자인 검수: 미실행, 캡처 준비 후 검토 예정.

기록은 작업 진행에 따라 후속 결과로 보완한다. 이 문서는 완료 보고가 아니다.

## Claude Code 1차 디자인 검수 반영 (해당 작업)

Claude Code가 이미지 20장을 직접 검수해 DR-01~22를 남겼다. Codex가 건너뛰기 링크의 숨김/키보드 노출, 모바일 차트 좌표와 격월·연도 라벨, 경로 이동 시 스크롤 초기화와 캡처 시 렌더 안정화, 변경 없는 발령 표기, 한국어 파일 선택과 크기, 행 오류 단일 알림·행/오류 수·한국어 항목명, 감사 펼침/접기, 내용 폭 배지, 상세 직급·상태, 발령 완료 문구·실제 날짜 범위·글자 수, 삭제 danger, 직급 부제, 역할 배지·로그인 부제, 감사 ID/대상 유형·가져오기 실패 설명을 반영했다.

DR-03은 목록에서 가져오기로 이동 후 렌더 완료를 기다리고 실제 scrollHeight 상한(데스크톱 1100/모바일 1300) 검사를 추가했다. 재촬영에서 통과했다. 이전 캡처는 라우트 렌더 완료 전 높이를 물려받을 수 있었으므로 스크린샷만으로 앱 결함으로 단정하지 않았다.

DR-06은 유지한다. '등록 내용 확인'은 API를 실행하지 않고 확인 대화상자만 연다. 다음 단계의 '전체 등록'이 실제 실행이다. DR-10은 기간 입력을 앞에 옮기되 기본 전체 기간을 유지한다. 과거 합성 기록이 초기 필터로 숨지 않게 하며 전체 기간임을 명시했다. 최근 기간 빠른 버튼은 이번 범위에서 생략했다. DR-21은 상세/수정 계층을 추가하되 셸에서 이름을 재조회하지 않고 '사원 상세'로 표시한다.

수정 후 npm test 45/45, npm run build PASS. npx playwright test 4/4 PASS: 기존 회귀 + 2단계 양 화면 흐름. 추가 캡처는 내 정보 본인 이력, 권한 없음, IMPORT_INVALID_FILE, 390x844 및 데스크톱 대화상자 뷰포트다. 대화상자 화면 내 경계, Esc 종료·실행 버튼 포커스 복귀를 실제 Chromium으로 확인했다. 정적 이미지로 스크린 리더·전체 포커스 순서·실측 대비 검증을 주장하지 않는다.

이미지 직접 열기는 검증 담당자 이미지 열기의 Windows 실행 환경 오류로 실패했다. 검수는 실제 이미지를 열 수 있는 Claude Code 디자인 검토에게 재요청하며, 검증 담당자은 Chromium의 실행 결과와 크기·넘침 검증을 제공한다. Python 실행 명령은 이 환경에서 실행되지 않아 파일 변경 없이 종료됐고, 승인된 Node 파일 편집으로 반영했다.

최종 세부 반영 확인: npm run typecheck 및 npm run build PASS. 상세 상태 배지 추가 후 기존 테스트의 단일 '퇴사' 텍스트 탐색이 두 요소를 찾아 실패하여 상태 dd로 범위를 한정했다(시나리오 유지). npm test 재실행 45/45 PASS. npx playwright test e2e/phase2.spec.ts 최종 2/2 PASS. 기존 Chromium 2개는 직전 전체 실행에서 PASS했다. jsdom 미지원 scrollTo 경고는 표준 문서 scrollTop 초기화로 바꿔 없어졌다. 검수 이미지 총28장을 해당 작업 Claude Code 재검수에 전달했으며 최종 디자인 판정은 대기 중이다.

## Claude Code 2차 검수 후 잔여 지적 반영

해당 작업: Claude Code가 갱신된 28장을 열어 높은 지적 3건 해결을 확인했다. 1차 지적은 해결16/부분3/유지·대안 수용3으로 분류했고 새 중간1/낮음5를 기록했다. 이는 실제 이미지 비교 결과이며 엔진 우열 수치가 아니다.

Codex는 NR-01 모바일 상단 바를 브레드크럼 첫 줄/사용자·로그아웃 둘째 줄의 고정 grid로 수정했다. NR-02 변경 전후 값을 span 하나로 묶었다. NR-03 느낌표를 제목 안으로 옮기고 NR-04 중복 취소 메시지를 제거했다(다른 서버 사유는 유지). NR-05 권한 없음에 내 정보 복귀 링크를 추가했다. NR-06 데스크톱 행 버튼을 32px로 줄였으며 모바일은 터치 조작을 위해 44px를 유지했다. U-10 가져오기 확인 대화상자를 두 화면 크기로 추가 촬영한다.

잔여 수정 검증: npm run typecheck, npm test 45/45, npm run build PASS. 전체 Chromium 실행에서 기존2개 PASS, 2단계2개는 CSS 느낌표가 제목의 접근 가능한 이름에 포함되어 실패했다. 장식을 aria-hidden span으로 옮긴 후 phase2 2/2 PASS, 최종 npm run build PASS. 빌드 청크 경고는 기존과 동일하다. 가져오기 확인 대화상자 2장을 포함해 캡처 총30장을 갱신했고 Claude Code에게 최종 잔여 지적 확인을 요청했다. 실제 백엔드 E2E는 여전히 미실행이다.

## 완료 보고 (해당 작업)

해당 작업 Claude Code 최종 검수: 높음·중간 잔여 0건, 디자인 기준 충족. 최종30장 중 변경 관련8장을 직접 재확인하고 나머지는 2차 판정을 유지했다. 누적28건은 해결24/부분 반영 후 수용1/유지·대안 수용3으로 기록됐다. 상세 근거·수용 사유·미확인은 docs/design/design-review-phase2.md 7절에 있다. 디자인 원본 및 세 차례 이미지 검수는 Claude Code, 구현·수정·실행 검증은 Codex가 맡았다.

최종 산출물: 1단계 화면 정비, 관리자 대시보드, 발령 등록/이력 및 본인 조회, 소속 미전송 수정, xlsx/CSV 입출력, 감사 로그, 계약 목업과 테스트, 디자인 시스템/시안/검수 기록, ADR0202/0203, README와 본 개발일지. 타입 검사·빌드 PASS, 기존16 포함45개 테스트 PASS, Chromium 기존2 + 2단계 양화면2 흐름 PASS. 마지막 장식 접근성 수정은 빌드와 2단계 Chromium 재실행으로 확인했다. 디자인 증거는 frontend/design-evidence/ 총30장이다.

실제 백엔드 E2E·MySQL 통합은 프론트 자체 작업에서 미실행이며 문서QA 통합 검수 대상이다. 스크린 리더, 실측 대비, 태블릿/확대 및 일부 상태 화면의 육안 검수는 미확인으로 유지한다. 목업의 ZIP 보안 한도·JWT·DB 원자성·collation 한계와 ExcelJS 큰 청크 경고는 README에 명시했다. backend/Compose/공통 문서 및 git 커밋은 변경하지 않았다. 검토 담당자에게 통합 검수 인계를 위해 완료 보고한다.
