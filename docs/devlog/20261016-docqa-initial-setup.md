# 2026-10-16 · 문서QA · 초기 세팅

## 작업 범위

설계 검토 검증 작업: EMS 폴더·Git·초기 문서 및 환경변수 예시 작성, 킥오프 결정 반영, 첫 커밋. backend/frontend는 빈 폴더 유지용 .gitkeep만 작성. 앱 구현과 통합 검수는 별도 작업 분담입니다.

## 수행 내용

README, .gitignore, .env.example, backend/frontend 및 docs/api의 .gitkeep, 요구사항·아키텍처·킥오프·AI 협업 기록, 일지·ADR 색인과 템플릿, ADR 0001, 회고 템플릿을 작성했습니다. 요구사항은 1~4단계 기능 ID와 MVP 인수 조건을 포함합니다.

## 판단 근거

- 킥오프의 논리 삭제·권한·토큰·삭제 거부 정책을 그대로 채택했습니다.
- ERD는 계정 분리 초안으로 표시하여 백엔드 최종 스키마와 대조할 여지를 남겼습니다.
- 환경변수는 실제 비밀값 대신 교체용 예시를 사용하며 키 이름은 백엔드 설정과 추후 대조합니다.
- 전달되지 않은 다른 팀의 2차 발언과 개발 환경 복구 원인은 추정하지 않았습니다.
- 부서·직급의 압축된 API 표기를 등록 POST 컬렉션, 수정 PUT/삭제 DELETE ID 경로로 풀어 적고 해석임을 표시했습니다.

## 문제와 해결

초기 조회에서 E:/portfolio/ems는 없었으며 E:/portfolio는 Git 저장소가 아니었습니다. 상위 E:/ 및 작업 루트의 AGENTS.md/CLAUDE.md는 발견되지 않았습니다. 기존 EMS 파일을 덮어쓰지 않고 새 프로젝트 구조를 만들었습니다.

## 검증

| 명령/검사 | 결과 |
| --- | --- |
| PowerShell 재귀 파일 열거 | 초기 파일 15개 확인 |
| Markdown 상대 링크 검사 | 백엔드 작성 예정 api/mvp-api.md 1건만 미생성; 문서에 예정 상태 명시 |
| git init | 첫 시도 .git Permission denied; 권한 승인 재시도 후 저장소 초기화 성공 |
| git check-ignore | .env/.env.local, Gradle build, node_modules, dist 제외 확인; .env.example은 제외되지 않음 |
| git status --short | 새 루트 파일 및 backend/docs/frontend 구조 확인 |
| 수동 문서 검토 | 1~4단계 ID, MVP 인수 조건, 구성도·ERD·계약, 회의·협업 기록 및 템플릿 확인 |

애플리케이션 빌드·테스트·MySQL 및 웹 통합 검수는 구현 전이므로 미실행입니다. 첫 커밋에는 위 초기 파일만 명시적으로 포함하며 커밋 해시와 최종 상태는 완료 보고에 남깁니다.

## 후속 작업

백엔드는 상세 API·최종 스키마·환경변수 계약을 제공하고, 프론트는 화면과 실제 API를 연결합니다. 문서QA는 설계 검토 별도 작업 분담 후 통합 검수 및 실행 절차·스크린샷·문서 정합성을 갱신합니다.
