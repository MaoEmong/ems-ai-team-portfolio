# Claude Code와 Codex를 활용한 개발

Claude Code와 Codex가 설계·백엔드·프론트·문서/QA 역할을 나눠 맡고 교차 검수했습니다. 사용자 요구를 API 계약과 인수 조건으로 정리하고, 구현 결과를 테스트·실제 화면·문서 근거와 대조했습니다. 개발에 사용한 두 도구와 제품의 Mock·Claude API·Ollama 제공자는 서로 다릅니다.

## 역할 분담과 기록 방식

- Claude Code는 설계 검토, UI 시안, 실제 이미지 검수를 수행했습니다.
- Codex는 백엔드·프론트 구현, 테스트, 문서 작성과 실제 통합 검수를 수행했습니다.
- 사용자 선택과 설계 검토에서 채택한 정책을 구분했습니다. 사용자가 직접 결정하지 않은 상세 정책을 사용자 승인으로 표현하지 않습니다.
- 요구사항 → API → ADR → 구현 → 개발일지 → 검수 결과를 연결했습니다. 담당 엔진이 확인되지 않은 기록은 추정해서 배정하지 않습니다.
- 계획된 수치와 실행 결과, 목업과 실제 API, 자동 검사와 이미지 직접 열람을 나눠 기록했습니다. 서로 다른 시점의 통과 수치를 합산하지 않습니다.

## 사례 1: 계약을 기준으로 병행 구현하고 실제 API로 대조

초기 계약 검토에서 퇴사자 수정·중복 퇴사의 400 제안 대신 409 EMPLOYEE_RETIRED를 채택했습니다. EMPLOYEE의 부서·직급 조회 범위, 생성201·수정/퇴사200·삭제204도 계약에 명시했습니다. 같은 계약을 기준으로 백엔드와 프론트를 구현하고, 목업 이후 Compose 3서비스와 실제 Chromium/API 20개 시나리오를 확인했습니다.

[백엔드 일지](devlog/20261016-backend-mvp.md), [프론트 일지](devlog/20261016-frontend-mvp.md), [실제 통합 검수](qa/2026-10-16-mvp-integration.md)

## 사례 2: 시안 → 구현 → 이미지 피드백 → 재검증

사용자는 구현과 디자인에 서로 다른 AI 도구를 활용하기를 원했습니다. Claude Code의 시안을 Codex가 구현하고 실제 이미지를 Claude Code가 검수한 뒤 Codex가 수정했습니다. 변경 후 재촬영·재확인으로 결과를 대조했습니다.

- 2단계: 이미지 검수3회, 지적28건 중 해결24·부분수용1·대안수용3, 높음/중간 잔여0. 최종30장 중 변경8장을 마지막에 직접 확인하고 나머지는 직전 판정을 유지했습니다. 모바일 상단 바, 중복 오류, 복귀 링크와 확인 대화상자가 수정 사례입니다.
- 3A: 수정 전95/95와 수정 후97/97을 구분했습니다. 15:36 타입·단일 전체테스트97/97·빌드,15:37 목업5174 Chromium6/6·재촬영24장입니다. Claude Code의 최초22장·지적18개(D3A-01~18), Codex 반영,24장 재확인을 연결했습니다. 높음/중간0, 낮음 N-01~07은 근거·위험을 기록해 수용했습니다.
- 3B: 최초42장(중간7) → 수정 후58장(새 중간2) → 수정 후63장 고정입니다. 마지막22장을 직접 확인하고41장은 직전 판정을 유지했습니다. 최종 재촬영63개는 검수본과 바이트 단위로 일치했습니다. 낮음3건을 수용했고 실측 대비·스크린리더·실제 API 등 미확인 범위는 남겼습니다.
- AI: Codex가70개와33개 테스트를 작성한 기록은 직접 실행과 구분했습니다. 최종18장 중6조각을 Claude Code가 직접 재확인하고 다른 구간은 직전 판정을 유지했습니다. 수용6건과 미확인은 원본 검수 기록에 남겼습니다.

위 수치는 엔진 우열·작업 시간 단축·비용 절감이나 품질 점수가 아닙니다. 이미지 검수는 실제 DB/API·실측 대비·스크린리더 검증을 대신하지 않습니다.

## 사례 3: AI 결과를 권한과 계약으로 제한

검색은 기존5필드와 C01 전체교체로 제한했습니다. 제안만으로 검색하지 않고 사용자의 명시적 적용 이후 기존 GET을 호출합니다. 확정 평가 요약은 허용된 본인·배정 평가자만 조회하고 원문·점수·등급을 바꾸지 않습니다. 합성 규정 Q&A는 문서ID·버전·절·발췌를 대조하며 인용 일치가 의미 정확성을 보장한다고 주장하지 않습니다.

Mock 실제HTTP·브라우저, 가짜키/로컬HTTP스텁 계약, 실제 Claude/Ollama 추론은 별도입니다. 실제 추론은 키·기존 서비스 미구성으로 미실행이며 키 탐색·모델 다운로드를 하지 않았습니다. 개발용 Claude Code/Codex가 제품 제공자의 실제 추론을 대신 검증한 것으로 쓰지 않습니다.

[AI API 계약](api/phase4-ai-api.md), [명시적 적용 ADR](adr/0206-ai-explicit-execution-and-ephemeral-results.md), [AI 통합 검수](qa/2026-10-16-phase4-ai-integration.md)

## 실패·수정과 검증 한계 보존

- 개발 중 진행 정보와 실제 산출물의 불일치, 검토 내용 전달 지연이 관찰됐습니다. 확인되지 않은 원인을 단정하지 않고 일지·이미지·실행 결과를 직접 대조해 검수가 완료되기 전 실기 검증을 보류했습니다. 기록의 접수 문제3건은 별도 자료로 교차 확인했으며 정상 접수와 혼동하지 않았습니다.
- 개발 세션이 끊겨 검토를 재개한 적이 있습니다. 정확한 원인·복구 조작을 직접 확인하지 못했으므로 특정 주체가 해결했다고 쓰지 않습니다. 누락된 범위는 기존 계약·기록으로 대조했습니다.
- CreateProcessWithLogonW1326·쓰기 권한 오류·Docker named pipe 접근 거부는 승인된 실행 환경으로 처리했습니다. Git 소유권 차이는 일회성 safe.directory로 처리했고 전역 신뢰·ACL을 바꾸지 않았습니다.
- Docker29.4.0에서 Testcontainers1.21.3의 HTTP400 연결 실패 뒤 공식 릴리스 근거로1.21.4로 갱신하고 MySQL 테스트를 통과했습니다. 해당 시점의 백엔드 실행을 QA가 새로 실행한 것처럼 쓰지 않습니다.
- 명령 반환 지연은 실제 빌드/MySQL 진행과 구분해 중복 기동을 피했습니다. 패치 적용 오류는 승인된 파일 쓰기 경로로 처리했습니다. 검토 중 실행을 보류한 기록은 제품 실패나 테스트 통과 근거가 아닙니다. webServer 무응답의 근본 원인은 미확정입니다.
- 파일 검사의 버튼명 불일치,3A 기동 직후 로그인 대기·'결근 판정 아님' 문구 오판은 QA 검사 오류였습니다.3B 첫 실패3건(부서 선택 누락·ADMIN 권한 기대값·응답 대기 누락)도 QA 스크립트 보정 후15/15 재통과했고 최초 JSON을 보존했습니다. 제품 결함으로 분류하지 않았습니다.
- AI 프론트 중간269/270과 최종276/10을 구분했습니다. 타입 확인 exit0과 시각 조회는 전체 테스트 통과가 아닙니다. bridge는404만 null로 처리하도록 수정하고 전체 검증했습니다.

## 실제 통합 검수와 공개 준비

3A 백엔드93/28·프론트97/6,3B 백엔드107/66·프론트166/8,AI 백엔드141/73·프론트276/10은 각각 해당 실행·목업 근거입니다. 예정된 평가29사례와 실제 MySQL31개를 구분했습니다. 테스트 작성만 한 기록을 빌드·Compose 실행으로 계산하지 않았습니다.

3B 인계 소스59개, AI 인계 소스129개는 당시 manifest와 일치했습니다. AI QA는21:11~21:18 KST에 유지DB 사전 스냅샷부터 실행해 V4의20업무테이블 보존, 기존62회귀·AI12개, 별도 새DB·대상명세26개, down·볼륨 유지를 확인했습니다. 정상 Mock에서 재현 불가능한 잘못된 제공자 출력·HTTP 봉투·지연·AI_BUSY·제공자 호출0회·전송 캡처는 테스트명과 시점에 연결해 QA 직접 미실행으로 남겼습니다. API 입력400과 제공자 출력502, 감사0건과 제공자 진입0회는 다릅니다.

2026-10-19에는 백엔드 integrationTest8suite79/79를 새로 실행했고 test/bootJar는 UP-TO-DATE로 기존147PASS를 재사용했습니다. 합산하지 않습니다. 포트폴리오 촬영은 실제API+Mock37화면53장이며 Claude Code 이미지 검수와 Codex 문서QA 대표3장 직접 확인을 구분했습니다. 새 고유 Compose 프로젝트에서 README 로그인·주요화면을 재현하고 down(-v없음)·볼륨보존·포트반환을 확인했습니다. 샌드박스 접근 거부와 QA 스크립트 준비 오류는 제품 결함이 아닙니다.
