# 단계별 회고

## 1단계 MVP 회고 초안 — 2026-10-16

문서QA Codex가 팀별 일지와 통합 검수에 근거해 작성한 초안입니다. 단계 종료 회의 및 사용자 최종 검수는 아직 수행했다고 기록하지 않습니다.

- **목표와 결과:** 사원·부서·직급 관리, 로그인·권한, 검색·필터·정렬·페이징 구현. 실제 API/Chromium 20개 통합 시나리오 통과. 백엔드 16개 테스트와 MySQL 통합 1개, 프론트 16개 테스트와 목업 Chromium 2개는 각 팀 일지의 수행 결과입니다.
- **잘된 점:** 계약을 먼저 확정하여 병행 구현 후 실제 로그인·CRUD 연동이 일치했습니다. 퇴사 시 기존 JWT 거부와 퇴사자 참조 삭제 거부를 명시해 정상 흐름 외의 업무 규칙도 검증했습니다. API 질의를 통해 400/409 차이를 구현 전에 정리했습니다.
- **문제:** 셸/파일/Docker 권한과 Testcontainers 호환 문제로 실행 경로 조정이 필요했습니다. 목업 검증만으로는 실제 연동 완료를 판단할 수 없었으며 별도 통합 과정이 필요했습니다. backend README 일부가 Compose 통합 전 설명을 유지하는 경미한 문서 불일치가 남았습니다.
- **개선:** 단계 시작 시 실행 계정·Docker 접근·도구 호환을 점검하고, 계약 변경 시 API뿐 아니라 팀 README도 동시 갱신합니다. 기능 ID별 실제/목업/미실행 증거를 나눕니다. 합성 QA 데이터는 유지 볼륨에 남으므로 반복 검수에 따른 누적을 안내합니다.
- **판단 주체:** 사용자는 범위·MySQL·배포 제외·두 LLM·Codex 중심 운영을 결정했습니다. HTTP 상태·구현 소유권은 설계 검토, 프론트 상태 관리·테스트 도구 대응은 담당 Codex의 판단입니다. 사람의 코드 검토나 비용 절감 수치를 만들어 기록하지 않습니다.
- **다음 행동:** 설계 검토에서 경미한 문서 결함 배정 및 단계 종료 판정. 2단계 세부 인수 조건은 다음 작업 분담 시 확정.

근거: [통합 검수](qa/2026-10-16-mvp-integration.md), [개발 일지 색인](devlog/README.md).

## 1단계 종료 회의 반영

[회의록](meetings/2026-10-16-phase1-closing.md): 계약 선확정·소유권 분리·목업 병행·실제 검수 분리·미실행 명시를 유지합니다. 프론트 자체 완료 시 실제 연동 미실행과 후속 QA20개 PASS는 서로 다른 시점입니다. 개발 세션 중단, 실행 계정·Docker 권한, Docker29/Testcontainers 문제는 일지의 근거로 설명합니다. 유지 DB는 기준값·증감, 새 DB만31명 시드를 기대합니다. DOC-01 수정본은 2단계 QA에서 재확인합니다.

## 2단계 회고 초안

- 목표: 대시보드·발령·파일·감사 및 역할별 엔진 배분.
- 잘된 점: 실제 다운로드 파싱·업로드 전체취소·감사 기간경계를 검수하고 디자인 피드백과 구현을 연결했습니다.
- 문제/해결: 실행 반환 지연은 빌드 진행 확인 후 재개, 편집 래퍼 오류는 승인 셸 사용. QA 버튼 선택자 오류는 앱을 바꾸지 않고 스크립트 수정.
- 디자인 근거: 지적28건 중 해결24·부분수용1·대안수용3, 높음/중간0. 목업 이미지 검수 범위를 넘는 효과 주장 없음.
- 실제 통합 결과·DB 경로·미실행: [QA 보고서](qa/2026-10-16-phase2-integration.md)에 최종 결과 기록.
- 판단 주체: 사용자 선호, 설계 검토 계약/분담, Claude 디자인 검수와 Codex 구현·검증을 구분.
- 다음 행동: 설계 검토의 단계 종료 판정과 다음 범위 확정. 이 초안은 사용자 최종 인수를 의미하지 않습니다.
