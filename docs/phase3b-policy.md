## 데모 급여

화면 제목·명세·README에 **“포트폴리오용 데모 급여 — 실제 세법·4대보험 산정 아님”**을 표시한다. 실제 법정 요율·세액 정확성을 주장하지 않는다. 파일 다운로드와 급여 알림은 범위 밖이다.

| 항목 | 결정 |
| --- | --- |
| 입력·JSON | 기본급·수당 각각0~1,000,000,000원 정수, JSON 정수 number. 문자열 아님 |
| 총지급 | 기본급+수당, 최대2,000,000,000원. JavaScript 안전정수 범위 안 |
| 공제 | 데모공제1/2/3은 총지급×450/350/300bps(4.5%/3.5%/3.0%) |
| 반올림 | 각 공제를 BigDecimal HALF_UP으로 원단위 반올림한 후 합산 |
| 실수령 | 총지급−총공제, 산식버전 DEMO_V1. 일할 계산 없음 |
| 대상 | hireDate<=해당월말, retireDate가없거나>=해당월초. 휴직자를 임의 제외하지 않음 |
| 월 유효성 | 미래월400·대상0명400 |
| 생성 | 월전체 원자적 생성, 설정누락409 SALARY_SETTING_MISSING·기존월409 PAYROLL_ALREADY_EXISTS·동시요청409 PAYROLL_BUSY |
| 재계산 | DRAFT에서 명시적으로 현재대상·설정으로 월전체 교체 |
| 확정 | 월전체 원자적 확정. CONFIRMED 이후 수정/삭제/취소/재생성409 PAYROLL_CONFIRMED |
| 스냅샷 | 이름·사번·부서·직급·직책·금액·비율·산식버전·생성자/시각·확정자/시각 |

### 급여 계산 기대값

아래 값은 정책의 계산 예시이며 테스트 실행 결과가 아니다. 총지급만 같으면 기본급/수당 구성에 관계없이 같은 공제를 적용한다.

| ---: | ---: | ---: | ---: | ---: | ---: |
|0|0|0|0|0|0|

### v1.1 대조 완료: 관리자 재배정 대상 조회

설계 검토 후속 결정(): 새 목록 API는 추가하지 않는다. ADMIN의 GET /evaluation-cycles/{id} 응답 assignments에 evaluationId, employee/reviewer({id,employeeNo,name}), state,incomplete,allowedActions를 추가한다. 점수·코멘트·등급·답변은없으며employee.employeeNo ASC,배정ID ASC순이다. 관계없는ADMIN의평가상세404는유지한다. 생성/수정 입력의employeeId/reviewerId쌍과다른주기API응답은그대로유지하며모든assignments에조회DTO를일괄적용하지않는다.

| 주기/평가서 | evaluationId/state | incomplete | allowedActions |
| --- | --- | --- | --- |
| DRAFT | null/null | false | [] |
| OPEN·미확정 | 생성된ID/현재state | false | [REASSIGN_REVIEWER] |
| OPEN·FINALIZED | 생성된ID/FINALIZED | false | [] |
| CLOSED·미확정 | 생성된ID/유지된state | true | [] |
| CLOSED·FINALIZED | 생성된ID/FINALIZED | false | [] |

위표는계약상기대값이며API실행결과가아니다. v1.1에서해당조회요약·정렬·액션조건을직접대조했고역슬래시코드구분자도제거됐음을확인했다. 최초v1(16:26:16,해시앞자리4CC9555A6D53)에서보고한조회경로누락과문서표시는계약문서상해결됐으며제품구현의동작판정은QA착수후다룬다.

등급 기대값:1.00→D,1.50→C,2.50→B,3.50→A,4.50→S,5.00→S. 경계 바로 아래/위, 평균 반올림, 본인 미공개 키 부재, 다른ADMIN404, 미배정/비활성/자기결재, 재배정 후 구평가자 권한과 관리자초안 초기화, 마감시 incomplete를 검사한다. 날짜 경과만으로 자동마감한다고 가정하지 않는다.

## V4·시드·기록

V1~V3은 불변이며 V4로 확장한다. 새DB는 부서계층·직책·기존31명 전원 급여설정·대상규칙에 맞는 직전월 CONFIRMED 명세·상태혼합 평가주기1개/합성코멘트를 제공한다. 기존 볼륨에는 자동 명세생성이나 재시드를 하지 않는다.

유지V3 업그레이드 전 기존컬럼/ID의 결정적스냅샷·행수·가능한체크섬을 보존한다. 테이블구조가 바뀐 전체체크섬은 기존컬럼 비교로 보완한다. 격리V3→V4, 실제유지보존, 새빈DB, 재시작검증을 구분한다. 이미V4인 재기동을 업그레이드라고 쓰지 않는다.

3B부터 세논리커밋(백엔드/프론트디자인/문서QA) 본문에 실제엔진과 역할을 기록한다. 기존3A 이력은 amend/rebase하지 않는다. 실제실행/미실행·검수주체·시점을 분리한다.
