### 매핑·규칙
| 영역 | 필드 | 규칙 |
|---|---|---|
| 기준일 | `asOfDate` | 머리 오른쪽 "기준일 YYYY-MM-DD (KST)". 화면 시계가 아니라 서버 값 |
| KPI 재직 인원 | `headcount.employed` | 보조 "재직+휴직 합계". 첫 카드는 primary-subtle 배경으로 강조 |
| KPI 재직/휴직/퇴사 | `active`, `onLeave`, `retired` | 배지와 같은 색 점 + 글자. 퇴사 보조 "퇴사 누적" |
| 이번 달 | `thisMonth.hires/retirements` | 기간 문구 "YYYY-MM-01 ~ asOfDate". 설명 "오늘까지 발생한 날짜만 셉니다." |
| 월별 차트 | `monthly[]` | 순서 그대로(오래된 달→최근). 제목 고정 "최근 12개월 월별 입사·퇴사 건수", 부제 "{첫 월} ~ {끝 월} · 월별 건수(월말 인원 아님) · 미래 날짜 제외" |
| 월별 표 | `monthly[]` | 열 `월 | 입사 | 퇴사`, 마지막 행 `합계`(프론트 합산, tfoot). 0도 0으로 표시 |
| 부서 분포 | `byDepartment[]` | 제목 "재직자 현재 부서별 분포", 부제 "재직·휴직 인원의 현재 소속 기준 (과거 시점 분포 아님)". 인원 내림차순, 같으면 이름순. 8개 초과 시 상위 7 + 기타 |
| 직급 분포 | `byPosition[]` | 제목 "재직자 현재 직급별 분포". `level` 오름차순(서열 순). 접지 않음(직급 수가 적음 가정, 12개 초과 시 차트 높이 증가) |
| 분포 표 | 각 배열 | 열 `부서 | 인원 | 비율` — 비율은 count/employed, 소수 1자리(프론트 계산, employed=0이면 "—") |

- count 0인 부서·직급이 응답에 있으면 차트에서는 생략하지 않고 0으로 표시(서버 응답을 그대로 반영). 응답에 없으면 만들지 않는다.
- "새로고침"은 secondary 버튼, 재조회 동안 기존 값 유지 + `aria-busy`.

### 반응형
- 태블릿: KPI 2×2, 이번 달 띠 1행, 분포 차트 세로 쌓기.
- 모바일: KPI 2×2(카드 숫자 24px), 월별 차트 높이 200px·라벨 격월, 분포 1열. "표로 보기" 동일.

### 상태
| 상태 | 표시 |
|---|---|
| 로딩 | KPI 카드 4개 틀 + 숫자 자리 스켈레톤, 차트 자리 240px 스켈레톤. `role=status` "대시보드를 불러오는 중…" |
| 오류 | 머리 아래 danger 알림 + [다시 시도]. 카드 영역은 그리지 않음 |
| 12개월 모두 0 | 월별 패널에 빈 상태 "최근 12개월 입사·퇴사가 없습니다" (표 보기 링크는 유지해 0 표를 확인 가능) |

## S2. 사원 상세 · 발령 등록 · 발령 이력

### 상세 (관리자 화면)
```
홈 / 사원 관리 / 홍길동
홍길동  [재직]                               [발령 등록] [정보 수정] [퇴사 처리]
E2024-031 · 개발팀 · 대리                      primary   secondary   danger

┌기본 정보─────────────────────────────────────────────────────┐
│ 이메일 hong@…      전화번호 010-…      입사일 2024-03-04          │
│ 역할   일반 사원     퇴사일  —                                    │
└────────────────────────────────────────────────────────────┘
┌발령 이력 (3건)────────────────────────────────────────────────┐
│ 발령일 기준 최신순 · 발령 기능 도입 이후 변경만 기록됩니다.            │
│ 발령일      부서               직급          사유          등록자    │
│ 2026-09-01 영업팀 → 개발팀     대리 (변경 없음) 조직 개편     관리자   │
│ 2026-03-01 영업팀 (변경 없음)   사원 → 대리     정기 승진     관리자   │
│ …                                                            │
│ 이전 1/1 다음                                                  │
└────────────────────────────────────────────────────────────┘
```
- 요약 머리: 이름(h1) + 상태 배지, 아래 `사번 · 부서 · 직급`(현재 소속).
- 기본 정보 dl: 데스크톱 3열, 태블릿 2열, 모바일 1열. 부서·직급은 머리에 있으므로 dl에서 제외하지 말고 유지해도 된다(현행 유지 가능). 빈 값 "—".
- 동작 버튼: 퇴사자는 [발령 등록][정보 수정][퇴사 처리] 모두 숨기고, 머리 아래 neutral 띠 "퇴사한 사원입니다 (퇴사일 YYYY-MM-DD). 정보 수정과 발령은 할 수 없습니다."

### 발령 이력 표
| 열 | 값 | 표시 |
|---|---|---|
| 발령일 | `effectiveDate` | tabular |
| 부서 | `fromDepartment.name` → `toDepartment.name` | 같으면 `이름` + muted "(변경 없음)", 다르면 `이전 → 이후`(이후 600). 화살표는 글자 "→", sr 텍스트 "에서 … 으로" |
| 직급 | `fromPosition.name` → `toPosition.name` | 위와 같음 |
| 사유 | `reason` | 최대 2줄 말줄임 없이 줄바꿈(200자 이하이므로) |
| 등록자 | `createdBy.name` | 처리 당시 이름 스냅샷. 링크 걸지 않음. 본인 화면에서도 표시(계약 응답에 포함) |
| 기록 시각 | `createdAt` | 데스크톱에서만 caption 크기로 발령일 아래 `기록 2026-09-01 10:12` |

- 정렬은 서버 고정(effectiveDate DESC, id DESC) 그대로, 프론트 재정렬 금지. 표 위 설명 "발령일 기준 최신순".
- 부서·직급 이름, 직급 정렬 순서(level), 등록자 이름은 모두 발령 당시 스냅샷이다. 표 아래 캡션 "부서·직급 이름과 등록자 이름은 발령 당시 값입니다. 이후 이름이 바뀌어도 이력은 그대로 남습니다."
- 그래서 이력의 최신 항목 `toDepartment.name`이 현재 소속 이름(요약 머리)과 다를 수 있다(부서 이름 변경 시). 이는 오류가 아니므로 경고를 띄우지 않는다. 직급 셀은 이름만 표시하고 level은 표시하지 않는다(필요 시 `title` 없이 생략).
- 페이지: size 10, 1페이지뿐이면 페이지 이동 숨김.

### 발령 등록 대화상자 (560px)
```
┌ 발령 등록 ───────────────────────────────────────────┐
│ 홍길동 (E2024-031)의 부서·직급을 변경합니다.               │
│ ┌현재 소속 ───────────────────────────┐                 │
│ │ 부서 개발팀     직급 대리              │ surface-subtle  │
│ └────────────────────────────────────┘                 │
│ 발령 후 부서 *          발령 후 직급 *                     │
│ [개발팀 (현재)    ▾]    [과장          ▾]                 │
│ 발령일 *                                                │
│ [2026-10-16]                                           │
│ 2026-09-01 ~ 2026-10-16 사이 날짜 (입사일·마지막 발령일 이후, │
│ 오늘까지. 미래 날짜는 등록할 수 없습니다)                     │
│ 사유 *                                       12 / 200   │
│ [정기 승진                                    ]          │
│ ⓘ 등록하면 현재 소속이 바로 바뀌고 이력에 남습니다. 되돌리려면     │
│   새 발령을 등록해야 합니다.                                 │
│                                    [취소] [발령 등록]    │
└──────────────────────────────────────────────────────┘
```
- 선택 상자 기본값 = 현재 부서/직급, 옵션 이름 뒤 "(현재)".
- 클라이언트 검증(서버가 최종): 부서·직급 둘 다 현재와 같으면 제출 시 상단 오류 "부서나 직급 중 하나 이상을 바꿔야 합니다." / 날짜 범위 위반 / 사유 공백·200자 초과. 사유 글자 수 카운터 `aria-live="polite"`는 180자 이상부터만 낭독.
- 날짜 `min`: max(hireDate, 이력 첫 항목의 effectiveDate). `max`: 오늘(서울). 기본값 오늘.
- 요청 본문: `{effectiveDate, departmentId, positionId, reason}` (둘 다 전송, 계약).
- 성공 201: 대화상자 닫기 → 상세 재조회(요약 머리의 현재 소속 갱신) + 이력 재조회 → 이력 패널 위 success 알림 "발령을 등록했습니다. 현재 소속: 개발팀 · 과장". 포커스는 알림으로.
- 오류: 400은 필드/상단, 409 EMPLOYEE_RETIRED는 design-system §9 문구, 기타는 상단.
- 확정 버튼은 primary(위험 아님, 되돌림은 새 발령). 첫 포커스는 "발령 후 부서".

### 사원 수정 (발령 반영)
```
소속 (읽기 전용)
┌──────────────────────────────────────────────┐
│ 부서  개발팀          직급  대리                  │ 점선 테두리, subtle 배경
│ 🔒 부서·직급은 발령 등록으로만 바꿀 수 있습니다.      │
│    [발령 등록하러 가기 →]                         │ → /employees/:id (대화상자 열기는 선택)
└──────────────────────────────────────────────┘
```
- 이 블록은 폼 컨트롤이 아니며 PUT 본문에서 `departmentId`·`positionId`를 **생략**한다.
- "🔒"는 장식(`aria-hidden`), 실제 이모지 대신 글자 "잠김" 배지(neutral)로 대체해도 된다.
- 409 APPOINTMENT_REQUIRED 수신 시 design-system §9 문구, 자동 재전송 없음.

### 내 정보 (일반 사원)
- 상세와 같은 머리·기본 정보 + "내 발령 이력" 패널. 동작 버튼 없음, 대화상자 없음.
- 빈 상태: "발령 이력이 없습니다 — 발령 기능 도입 이후의 부서·직급 변경만 기록됩니다." (버튼 없음)
- 다른 사원 경로 접근(403)은 오류 패턴.

### 모바일
- 머리 동작 버튼 3개 → 전체 폭 세로 쌓기 대신 [발령 등록] + [더보기 ▾](정보 수정, 퇴사 처리) 권장. 구현 부담 시 세로 쌓기 허용(퇴사 처리는 마지막).
- 이력은 카드(design-system §5.1).

## S3. 엑셀 가져오기 (`/employees/import` 제안)

### 단계 구성 (한 화면, 위→아래)
```
홈 / 사원 관리 / 엑셀 가져오기
엑셀로 사원 한 번에 등록

┌ ⓘ 가져오기 규칙 ──────────────────────────────────────────────┐
│ • 한 행이라도 오류가 있으면 **모든 행의 등록이 취소**됩니다.          │
│   오류를 모두 고친 뒤 파일 전체를 다시 올려 주세요.                  │
│ • .xlsx 파일, 5MiB 이하, 데이터 1,000행 이하 (머리글 제외)         │
│ • 내려받은 양식의 employees 시트·머리글을 바꾸지 마세요.             │
│ • 사번·입사일·초기 비밀번호 칸은 '텍스트' 서식이어야 합니다           │
│   (숫자·날짜 서식은 자동 변환하지 않고 오류 처리). 날짜는 YYYY-MM-DD. │
│ • 수식 칸은 거절됩니다. 앞뒤 공백도 그대로 검사됩니다.               │
│ • 완전히 빈 행은 건너뜁니다. 오류 행 번호는 엑셀 화면 번호 그대로입니다. │
│ • 등록된 사원은 모두 '재직' 상태로 시작합니다.                     │
└──────────────────────────────────────────────────────────┘
① 양식 내려받기   [↓ 업로드 양식 (.xlsx)]  부서·직급 ID 목록 시트 포함
② 파일 선택       [파일 선택] employees-2026-10.xlsx · 0.4MiB   [선택 해제]
③ 등록           [가져오기 실행]  ← primary, 파일 없으면 비활성 + "파일을 먼저 선택하세요"
```
- 파일 선택: `<input type="file" accept=".xlsx,application/vnd.openxmlformats-officedocument.spreadsheetml.sheet">` + 라벨. 선택 후 파일명·크기 표시. 클라이언트 사전 검사(확장자, 5,242,880바이트) 실패 시 필드 오류, 실행 버튼 비활성.
- 실행 클릭 → 확인 대화상자 없음(전부 취소 규칙상 부분 저장 위험 없음). 대신 실행 중:
  - 버튼 `검사하고 등록하는 중…`, 파일 선택·선택 해제 비활성(중복 제출 방지), 상단 `role=status` "파일을 검사하고 등록하는 중… 창을 닫지 마세요."
- 결과 영역은 ③ 아래 고정 위치, 새 결과가 나오면 결과 제목으로 포커스 이동.

### 결과 — 성공 (201)
```
┌ ✓ 42명을 등록했습니다. ─────────────────────────────┐ success
│ 파일: employees-2026-10.xlsx                        │
│ [사원 목록에서 보기]  [다른 파일 가져오기]              │

```

### 결과 — 전부 취소 (400 IMPORT_VALIDATION_ERROR)
```

│ 파일의 5개 행에서 오류 7건을 찾았습니다. 어떤 행도 등록되지 않았습니다.  │
│ 오류를 모두 고친 뒤 파일 전체를 다시 올려 주세요.                      │
└──────────────────────────────────────────────────────────┘
오류 목록 (7건)
┌───────┬───────────────┬──────────────────────────────────┐
│ 행 번호 │ 항목            │ 사유                               │
├───────┼───────────────┼──────────────────────────────────┤
│     3 │ 이메일 (email)   │ 이미 사용 중인 이메일입니다.            │
│     3 │ 입사일 (hireDate)│ YYYY-MM-DD 형식이 아닙니다.           │
│     8 │ 사번 (employeeNo)│ 파일 안에서 7행과 중복됩니다.           │
│   ... │                │                                   │
└───────┴───────────────┴──────────────────────────────────┘
행 번호는 엑셀 화면의 행 번호입니다 (1행 = 머리글, 데이터는 2행부터, 빈 행도 번호를 셉니다).
사번·날짜·초기 비밀번호 칸은 엑셀에서 '텍스트' 서식이어야 합니다.   ← '문자열 서식 필요' 사유가 있을 때만
```
- 예: 5행이 완전히 빈 행이면 건너뛰므로 다음 데이터의 오류는 6행으로 표시된다(번호를 당기지 않음). 화면은 서버 row 값을 그대로 쓰고 다시 계산하지 않는다.
- 표 데이터 `rowErrors[{row, field, reason}]`. 정렬: row 오름차순, 같은 행은 응답 순서 유지. 상단 문구의 "N개 행"은 고유 row 수, "오류 M건"은 배열 길이(프론트 계산).
- 항목 열: 알려진 field는 `한국어 (원래 키)`, 모르는 키는 원래 키(mono). field가 비면 "행 전체".
- 사유는 서버 문구 그대로 텍스트로. 입력 원문 값은 계약상 오지 않으며 화면도 만들지 않는다.
- 100건 초과 시 표 높이 480px 내부 스크롤 + 머리글 고정(sticky). 페이지 나누지 않음(최대 1,000행 × 필드 수 규모).
- "오류 목록 복사" 같은 부가 기능은 이번 범위에서 만들지 않는다.

### 결과 — 기타 실패
| 코드 | 표시 |
|---|---|
| 413 FILE_TOO_LARGE | danger 띠 "파일이 5MiB를 넘습니다", 표 없음 |
| 400 IMPORT_INVALID_FILE | danger 띠 "파일 전체를 처리할 수 없어 아무것도 등록되지 않았습니다" + 서버 message + 확인 목록(형식·시트·머리글 / 데이터 1~1,000행 — 빈 파일·초과 포함 / 손상·암호 / 압축 해제 한도) + 양식 다시 내려받기 링크. 표 없음 |
| 409 IMPORT_CONFLICT | danger 띠, §9 문구. **행 번호 표 없음** |

- 모든 실패 공통: 선택한 파일은 유지(고친 파일로 바꾸기 쉽게 [다른 파일 선택] 강조), 실행 버튼 다시 활성.

## S4. 내보내기·양식 (사원 목록 머리)

```
사원 관리                               [내보내기 ▾] [가져오기] [+ 사원 등록]
                                        ┌────────────────────────┐
                                        │ 현재 조건의 전체 결과 128명 │ caption
                                        │ Excel (.xlsx)          │
                                        │ CSV (.csv, UTF-8)      │
                                        │ ────────────────        │
                                        │ 업로드 양식 (.xlsx)      │
                                        └────────────────────────┘
```
- 메뉴 대신 버튼 2개(`xlsx로 내보내기`, `CSV로 내보내기`)로 펼쳐 놓아도 된다(구현 단순). 메뉴를 쓰면 `aria-haspopup="menu"`, 화살표 키 이동, Esc 닫기.
- 메뉴 머리 caption: "현재 검색·필터·정렬의 **전체 결과 {totalElements}명** (페이지 구분 없음)". 페이지 크기·현재 페이지는 적용하지 않는다는 것을 글로 말한다.
- 요청 파라미터: `format, keyword, departmentId, positionId, status, sort` — **page·size 제외**, 클릭 시점 값으로 고정. 빈 값 파라미터는 보내지 않는다.
- totalElements > 10,000이면 항목을 비활성으로 두고 "10,000명 초과 — 필터로 줄여 주세요" 표시(서버 400도 같은 문구로 처리).
- 진행: 버튼 `파일 만드는 중…` → 완료 시 목록 위 info/success 띠 "파일을 만들었습니다: ems-employees-20261016.xlsx" (Content-Disposition 파일명 표시, 못 읽으면 기본 이름). 4초 후 자동으로 사라지지 않게 한다(닫기 버튼).
- 결과 0명이어도 내보내기 허용(머리글만 있는 파일). caption "결과가 0명입니다. 머리글만 있는 파일이 만들어집니다."
- 가져오기 버튼은 S3 화면으로 이동. 양식 다운로드는 S3에도 있다(두 곳).

모바일: 머리 동작 3개 → [+ 사원 등록] 전체 폭 + [내보내기·가져오기 ▾] 하나로 합침.

### 필터 ↔ 쿼리
| UI | 쿼리 | 규칙 |
|---|---|---|
| 기간 시작일 F | `from` | `F` + `T00:00:00+09:00` |
| 기간 종료일 T | `to` | **T 다음 날** + `T00:00:00+09:00` → [from, to). 화면에는 "종료일 포함"이라고 쓴다 |
| 빠른 기간 | from/to | 오늘: F=T=오늘(서울). 7일: F=오늘-6. 30일: F=오늘-29 |
| 행위 | `action` | 선택 목록은 계약의 action 전체, 한국어 라벨(아래) |
| 결과 | `success` | 전체/성공(true)/실패(false) |
| 대상 유형 | `targetType` | 전체/사원/부서/직급 |
| 대상 ID, 행위자 ID | `targetId`, `actorId` | 숫자 입력(`inputmode="numeric"`). 도움말 "사원 상세 주소의 번호" |
| 페이지 | `page,size` | 필터 변경 시 page=0 |

- 기본값: 최근 7일. 시작일 > 종료일이면 필드 오류 "시작일이 종료일보다 늦습니다." 조회하지 않음.
- 검색어 입력은 즉시 조회하지 않고 [조회]로 확정(감사 조회 부하·의도 명확). 선택 상자도 [조회]로 통일.
- 필터 상태를 URL 쿼리에 반영(새로고침·공유 시 유지) — 권장, 필수 아님.

### 행위 라벨
| action | 라벨 | action | 라벨 |
|---|---|---|---|
| LOGIN_SUCCESS | 로그인 | LOGIN_FAILURE | 로그인 실패 |
| EMPLOYEE_CREATE | 사원 등록 | EMPLOYEE_UPDATE | 사원 수정 |
| EMPLOYEE_RETIRE | 퇴사 처리 | APPOINTMENT_CREATE | 발령 등록 |
| DEPARTMENT_CREATE/UPDATE/DELETE | 부서 등록/수정/삭제 | POSITION_CREATE/UPDATE/DELETE | 직급 등록/수정/삭제 |
| EMPLOYEE_IMPORT | 사원 가져오기 | EMPLOYEE_EXPORT | 사원 내보내기 |
| (알 수 없음) | 원래 코드값 그대로 | | |

### 표 셀
- 행위자: `actor` 있으면 `이름 (사번)` — **기록 당시 스냅샷**. null이면 muted "확인 불가"(없는 계정으로 로그인 시도 등). 링크 없음(행위자 사원이 퇴사·이름 변경됐을 수 있음).
- 대상 셀은 action별로 아래 표를 따른다. `targetLabel`은 기록 당시 이름 스냅샷.

| 경우 | 계약 값 | 대상 셀 표시 |
|---|---|---|
| 로그인 성공·실패 | targetType·targetId·targetLabel 모두 null | muted "해당 없음" |
| 가져오기·내보내기 | targetType=EMPLOYEE, targetId·targetLabel null | `[사원]` 배지 + muted "여러 사원(개별 대상 없음)" |
| 사원·발령·퇴사 | EMPLOYEE + id + label | `[사원]` 배지 + `targetLabel` (사원 상세 링크, targetId 사용) |
| 부서·직급 | DEPARTMENT/POSITION + id + label | `[부서]`/`[직급]` 배지 + `targetLabel` (링크 없음 — 삭제됐을 수 있음) |
| 그 밖의 null | — | "해당 없음" |

- 대상 유형 필터에서 '사원'을 고르면 가져오기·내보내기 기록도 함께 나온다(계약상 대상 유형 EMPLOYEE). 필터 도움말: "사원에는 엑셀 가져오기·내보내기 기록도 포함됩니다."
- 결과 배지 성공/!실패.
- 상세: 행 끝 [상세] 버튼 → **오른쪽 패널(데스크톱 480px 드로어) 또는 행 아래 펼침**. 권장은 행 아래 펼침(`aria-expanded`, 구현 단순, 모바일 동일). 한 번에 하나만 펼침.

### 상세 펼침
```
┌ 발령 등록 · 2026-10-16 14:02:11 · 성공 ─────────────────────────┐
│ 행위자 관리자 (A0001)   대상 사원 · 홍길동 (ID 31)                   │
│ 변경 내용                                                       │
│ 항목        변경 전          변경 후                                 │
│▌부서        영업팀           개발팀           [변경]                  │
│▌직급        대리             과장             [변경]                  │

│ 부가 정보                                                        │

```
- 규칙은 design-system §3.9. 펼침 상단 캡션 "이름·부서·직급은 기록 당시 값입니다. 현재 값과 다를 수 있습니다."
- 생성 → 변경 전 "해당 없음", 삭제 → 변경 후 "해당 없음".
- 로그인·가져오기·내보내기 → before/after 모두 null → `변경 전 해당 없음 · 변경 후 해당 없음` + "이 기록은 개별 값 변경을 담지 않습니다." + 부가 정보.

action별 부가 정보 예
| action | 부가 정보 표시 |
|---|---|
| LOGIN_SUCCESS | "부가 정보 없음" |
| LOGIN_FAILURE | 사유: 아이디 또는 비밀번호 불일치 / 비활성 계정. 행위자 null이면 캡션 "존재하지 않는 아이디로 시도한 기록이며, 입력한 아이디는 저장하지 않습니다." |
| EMPLOYEE_IMPORT 성공 | 가져온 건수 42 + 캡션 "사원별 내용은 같은 시각의 '사원 등록(출처: 엑셀 가져오기)' 기록에서 확인하세요." |
| EMPLOYEE_IMPORT 실패 | 상단 neutral 띠 "이 가져오기는 전부 취소되어 등록된 사원이 없습니다." + 오류 코드(IMPORT_VALIDATION_ERROR 등) + 오류 수(파일 전체 오류는 1) |
| EMPLOYEE_EXPORT 성공 | 형식 xlsx · 내보낸 행 수 128 + **내보내기 조건** 소표(검색어 / 부서 ID / 직급 ID / 재직 상태 / 정렬, 빈 값 "조건 없음") + 캡션 "성공은 서버가 파일을 만들었다는 뜻이며, 사용자의 저장 완료를 뜻하지 않습니다." |
| EMPLOYEE_CREATE (가져오기) | 출처: 엑셀 가져오기 |
| APPOINTMENT_CREATE | 발령 ID |
- 모든 값은 텍스트 노드. 객체는 `<pre>` 텍스트.

### 상태
- 로딩: 필터는 즉시, 표 자리 스켈레톤. 오류: 표 자리 danger + 다시 시도. 빈 결과: design-system §4.2 문구(기간 설명 포함). 권한: EMPLOYEE 메뉴 없음, 직접 접근 시 권한 없음 패널.

- 필터: 기간 + [필터 (n)] 펼침. 표 → 카드(design-system §5.1), [상세]는 카드 아래 펼침, 전후 표는 3열 유지(항목 열 30%).

## S6. 부서·직급 관리 (1단계 개선)

- 레이아웃 유지(목록 1.6fr + 양식 1fr, 태블릿 이하 1열, 모바일은 **양식이 위**: 등록이 주 동작).
- 머리 설명 교체: "현재 소속 사원(퇴사자 포함)이나 과거 발령 이력에 쓰인 {부서/직급}은 삭제할 수 없습니다. 이름 변경은 가능합니다."
- 수정 중인 행은 primary-subtle 배경 + 양식 제목 "부서 수정 — 개발팀". 수정 취소 시 포커스를 해당 행의 [수정] 버튼으로 복귀.
- 직급 표 열 이름은 "정렬 순서"를 유지한다(level의 높고 낮음 의미는 계약에 없으므로 문구로 단정하지 않는다).
- 삭제 409 문구는 design-system §9.
- 표 행 동작 버튼 크기 sm(32px), 삭제는 danger 스타일.

## S7. 사원 목록·등록 폼 (1단계 개선)

### 목록
- 머리: S4 버튼 배치. 결과 요약 줄 `총 128명 · 상태: 재직·휴직 · 부서: 전체 · 정렬: 사번 오름차순`.
- 필터 기본값 표시 "재직·휴직"(현행 유지 — 서버 기본 동작 RETIRED 제외와 일치, 2026-10-16 프론트 담당 확인).
- [필터 초기화] ghost 버튼을 필터 줄 끝에(필터가 기본값과 다를 때만).
- 표 열: 사번(tabular) | 이름(링크) | 부서 | 직급 | 입사일 | 상태 배지. 행 높이 44px.
- 모바일 카드(design-system §5.1).
