## 2. 정책 연결 확인 (이미지에 보이는 범위)

정책(전달): PENDING은 날짜 무관 본인 CANCEL, 시작일 지난 PENDING은 다른 관리자 REJECT만(승인 409), APPROVED는 시작 전 본인 CANCEL. UI는 allowedActions만 사용.

| 장면 | 보이는 버튼 | 판단 |
|---|---|---|
| 본인 PENDING 상세 (#6, #17) | [신청 취소] | 정책과 일치 |
| 다른 관리자의 PENDING 상세 (#8) | [승인][반려] | 정책과 일치 |
| 관리자 시점 APPROVED (#9, #20) | 없음 + "현재 처리할 수 있는 동작이 없습니다." | 신청자가 아니므로 CANCEL 없음 — 일치 |
| 본인 CANCELLED (#10, #21) | 없음 + 같은 문구 | 일치 |

- 화면이 날짜로 버튼을 고르는지는 이미지로 증명할 수 없다. 위 표는 "보이는 버튼이 정책 결과와 모순되지 않는다"는 확인이다.
- 이미지에 없는 정책 장면은 §5 미확인으로 남긴다.
- 시안 갱신: 이 정책에 맞춰 phase3a-screens.md §3.5(LEAVE_START_PASSED는 승인된 휴가 취소에만)와 §9.2를 고쳤다.

### 시안과 달라도 문제로 보지 않은 것 (수용 제안)
- 휴가 신청이 모달이 아니라 페이지 안 폼(#5)이다. 종류도 radio가 아니라 select다. 흐름과 정보가 같아 문제 없다.
- 결재 목록(#7)에 행 승인·반려 버튼이 없고 상세에서 처리한다. allowedActions 사용과 요약 확인이 상세에서 이루어져 오히려 안전하다.
- 알림이 드롭다운이 아니라 중앙 대화상자(#11)다. 포커스 가둠만 지켜지면 문제 없다(§5).
- 월 이동이 이전/다음 버튼 없이 month 입력 하나다. 기능은 같다.

## 8. 최종 수용 판단 (Codex)

§6은 1차 검수 시점의 후속 계획이며, 실제 재확인은 §7에서 완료했다. 최초 D3A-01~18은 §7.2에 같은 ID로 반영·수용 근거와 Claude 재확인 판정을 연결했다. 높음·중간 잔여는 0이다. 아래 새 낮음 7건은 Claude가 비차단으로 분류했고, Codex가 이번 단계의 알려진 잔여 사항으로 수용한다. 코드 추가 변경은 하지 않았으므로 15:36~15:37 최종 소스의 타입 검사·전체97/97·빌드·Chromium6/6은 유효하다. 수용은 사용자의 별도 결정으로 기록하지 않는다.
