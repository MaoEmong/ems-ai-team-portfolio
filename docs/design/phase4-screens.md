## 0. 공통 원칙

| 원칙 | 화면 규칙 (계약 근거) |
|---|---|
| 자동 호출 없음 | 화면 진입·패널 펼침·입력·탭 전환으로는 AI POST를 보내지 않는다. **[실행] 버튼을 눌렀을 때만** 요청한다. 실패·취소 뒤 자동 재호출, 카운트다운 실행, 백오프는 없다(§1, §7 "서버 자동 재시도 0") |
| 실행 전 고지 | 실행 버튼 바로 위에 `GET /ai/config` 고지 블록을 둔다(§1). 고지 외 승인 단계(동의 체크박스·확인 모달·동의 플래그)는 만들지 않는다(계약 §1 "별도의 승인 API나 동의 플래그는 추가하지 않는다") |
| Mock 대체 없음 | 실패해도 Mock 결과를 대신 보여 주지 않는다(계약 머리). Mock 배지는 `meta.mock`이 true일 때만 단다 |
| AI 결과임을 표시 | 결과는 항상 "AI 생성 결과" 카드 안에 둔다. 사람이 쓴 원문·서버 확정값과 같은 블록에 섞지 않는다 |
| 텍스트 전용 | `message`·`summary`·`answer`·`excerpt`·`notice`는 일반 텍스트로만 렌더링한다(계약 §6 "HTML로 렌더링하지 않는다"). 마크다운 해석, 자동 링크, 이미지를 금지한다. 줄바꿈만 살린다 |
| 원문 비저장 | 질문과 결과를 URL 쿼리, localStorage·sessionStorage, history state에 넣지 않는다. 화면을 떠나면 사라진다. 서버도 결과를 DB에 저장하지 않는다(계약 §9) |
| 판정은 서버 | AI-01 적용 뒤 조회와 권한 검사는 기존 `GET /employees`가 한다. AI-02는 원문·점수·등급을 바꾸지 않는다. AI-03 인용 원문 일치는 서버가 검증한다. 화면은 받은 값만 그린다 |
| 민감 정보 최소 노출 | 결과 본문과 입력 원문을 토스트, `role=status`, `<title>`, 브레드크럼, URL에 넣지 않는다. live region 문구는 짧은 상태뿐이다 |
| 분기는 code | 오류는 `code`로 문구를 고르고, 다시 실행 지름길은 `retryable`로 정한다(§2.3). `message`는 보조다 |
| 접근성 | design-system §6 그대로. AI 전용 규칙은 §7 |

## 1. 실행 전 고지 블록 (3기능 공통 컴포넌트)

**데이터**: `GET /ai/config` → `{provider, model, mock, externalTransfer, enabled{employeeSearch, evaluationSummary, policyQa}, promptVersion}`. 모든 인증 사용자가 쓸 수 있고, 분당 제한에는 들어가지 않는다.

### 1.1 배치 (데스크톱)
```
┌ AI 실행 안내 ──────────────────────────────────────────────┐
│ 제공자 ollama · 모델 {model} · 프롬프트 버전 ems-ai-v1           │
│ ⓘ 실행하면 아래 자료가 EMS 서버 밖의 AI 제공자로 전송됩니다.        │
│   전송: {기능별 전송 필드 — §1.2}                                │
│   제외: {기능별 제외 필드 — §1.2}                                │
│   입력한 글에 개인정보를 넣지 마세요. 자유 텍스트 속 개인정보는        │
│   자동으로 지워지지 않습니다.                                      │
│ 실행 기록(기능·제공자·모델·소요 시간)은 감사 로그에 남고,            │  muted
│ 질문·결과 원문은 저장되지 않습니다.                                 │
└────────────────────────────────────────────────────────────┘
                                                 [AI로 {동작}]
```
- info 띠(design-system §3.6) 하나로 그린다. 닫기 버튼은 없다. 고지와 실행 버튼은 같은 패널에 두고 고지를 버튼 바로 위에 둔다.
- 제공자 표시 이름은 `mock` → "Mock", `anthropic` → "Anthropic", `ollama` → "Ollama"다. 그 밖의 값은 서버 문자열을 그대로 쓴다. 모델·버전은 서버 문자열 그대로이며 빈 값은 "—"다.
  - Ollama 모델이 빈 값이면 서버 실행 시 503이 날 수 있다. 고지는 "—"만 보이고 판단하지 않는다.
- `mock`이 true면 첫 줄 옆에 "Mock · 실제 추론 아님" 배지를 단다. 그 아래 muted 글자 "결정적인 시연 결과입니다. 실제 자연어 이해 결과가 아닙니다."를 둔다.
- **`externalTransfer`**: 계약상 `mock`=false, `anthropic`=true, `ollama`=true다.
  - true: 위 전송 안내를 보인다. **Ollama도 true다.** 문구는 "EMS 서버 밖"이라고 쓰고 "클라우드"·"인터넷" 같은 말은 쓰지 않는다. Ollama는 외부 프로세스일 뿐 클라우드라는 뜻이 아니다(계약 §1).
  - false: "외부로 전송하지 않습니다." 한 줄로 쓴다. 개인정보 안내 문장은 남긴다.

### 1.2 기능별 전송·제외 문구 (계약 §5 표 그대로)
| 기능 | 전송 | 제외 |
|---|---|---|
| AI-01 | 입력한 질문, 지원 필터 형식, 부서·직급 ID와 이름 목록 | 사원 목록, 이름·사번·연락처·급여·평가 정보, 직책 목록 |
| AI-02 | 평가 항목 이름, 항목별 자기평가·관리자 코멘트 | 평가·사원·평가자 ID, 이름, 사번, 연락처, 급여, 점수, 등급 |
| AI-03 | 입력한 질문, 합성 규정 문서(ID·버전·절·본문) | 실제 직원 정보, 실제 회사 규정, HR 업무 원문 |

- 서버는 전송 문구를 주지 않는다. 이 표는 계약 §5를 화면 문구로 옮긴 고정 문구다. 계약 §5가 바뀌면 같이 고친다.
- 문구 끝에 동의 유도 문장을 붙이지 않는다. 실행 버튼이 곧 명시 실행이다.

### 1.3 설정 조회 상태
| 상태 | 화면 |
|---|---|
| 조회 중 | 고지 자리에 스켈레톤 2줄. 실행 버튼 비활성, 라벨 "설정 확인 중…" |
| 실패(네트워크·5xx) | danger 띠 "AI 설정을 불러오지 못했습니다. 실행할 수 없습니다." + [다시 불러오기]. 설정 없이 실행하는 대체 경로는 없다 |
| 해당 기능 `enabled` false | 고지·입력 대신 neutral 띠 "이 기능은 현재 꺼져 있습니다." 실행 버튼은 그리지 않는다. 켜는 화면은 없다(서버 환경 설정 §8) |
| 성공 | 고지 표시, 입력 조건을 채우면 실행 버튼 활성 |

- `enabled`는 기능 설정일 뿐이다. 사용자 권한이나 호출 성공을 뜻하지 않는다(계약 §1). 권한에 따른 표시는 화면별 규칙(§3·§4·§5)이 따로 정한다.
- 설정은 화면(패널) 진입 시 1회 조회한다. 실행 결과가 503 `AI_DISABLED`면 설정을 다시 조회한다(§2.3).

### 1.4 모바일 (390)
- 고지는 접지 않는다. 전송·제외 줄은 줄바꿈되어도 다 보인다.
- 실행 버튼은 전체 폭, 고지 바로 아래.

## 2. 실행 · 진행 · 결과 공통

### 2.1 진행 · 중복 방지 · 취소
```
[AI로 필터 제안 중…  ◌] (비활성)          [요청 취소]
ⓘ 요청을 중단해도 제공자 쪽 처리와 비용이 취소된다는 보장은 없습니다.
```
- 응답은 비스트리밍이다. 완성 응답만 표시하고 글자가 흘러나오는 연출은 하지 않는다.
- 화면 안 중복 방지: 버튼을 누르는 즉시 비활성으로 바꾸고 라벨을 "…중"으로 바꾼다. 영역에 `aria-busy="true"`를 두고 입력란은 읽기 전용으로 바꾼다.
- 서버는 사원별로 AI POST 1건만 동시에 처리한다(계약 §6). 다른 탭이나 다른 AI 기능이 진행 중이면 429 `AI_BUSY`가 온다(§2.3). 화면이 다른 탭 상태를 추측해 막지는 않는다.
- **[요청 취소]**: 브라우저 요청을 끊는다(AbortController 제안). 진행 중에는 muted 글자로 비용 미보장 안내를 둔다.
  - 취소 뒤에는 neutral 띠 "요청을 취소했습니다. 결과는 표시하지 않습니다."를 둔다. 늦게 온 응답은 버린다.
  - 같은 띠에 보조 글자 "서버가 앞 요청을 마무리하는 동안 바로 다시 실행하면 '다른 AI 요청 처리 중'이 나올 수 있습니다."를 둔다. 계약상 슬롯은 서버 처리가 끝나야 풀리기 때문이다.
- 시간 제한은 서버가 정한다(제공자 호출 기본 30초 → 504 `AI_TIMEOUT`). 화면은 따로 타이머를 두지 않고 진행률이나 남은 시간도 보이지 않는다.

### 2.2 결과 카드와 meta
```
┌ AI 생성 결과 ─────────────────────── [Mock · 실제 추론 아님] ┐
│ (본문 — 기능별)                                            │
│ ───────────────────────────────────────────────────────── │
│ Ollama · {model} · ems-ai-v1 · 2026-10-16 20:00 생성         │ caption, muted
│ 요청 ID 94ee406e-e92a-4f9b-bc35-78617af97820                │ mono, caption
│ ⓘ AI가 생성한 보조 결과이며 틀릴 수 있습니다. 원문을 확인해 주세요.  │
└──────────────────────────────────────────────────────────┘
```
- 메타데이터 줄은 응답 `meta{requestId, provider, model, mock, externalTransfer, promptVersion, generatedAt}`의 값을 쓴다. 실행 전 고지값(config)이 아니라 meta 값이 그 결과의 실제 값이다. 둘이 달라도 화면은 맞추지 않는다.
  - `generatedAt`은 서울 오프셋이 들어 있다. `YYYY-MM-DD HH:mm 생성`으로 표기만 바꾼다.
  - `requestId`는 원문을 담지 않은 서버 UUID다. 문의·감사 대조용으로 caption mono로 보인다(`〈확인 C-03〉`).
  - `meta.mock`이 true면 카드 머리에 Mock 배지를 단다. `meta.externalTransfer`는 카드에 다시 쓰지 않는다(고지에서 이미 알렸다).
- 새 실행을 하면 이전 카드를 지우고 바꾼다. 결과 이력은 두지 않는다. 복사 버튼도 두지 않는다(텍스트 선택은 막지 않는다).
- **결과 낡음**: 결과가 나온 뒤 입력이 바뀌면 카드 위에 warning 글자 "입력이 바뀌었습니다. 이 결과는 이전 입력 기준입니다."를 붙인다. AI-01은 이때 [제안 적용]을 비활성으로 바꾼다(§3.4).

### 2.3 오류 (`code` 기준 · `retryable` 지름길 · 자동 재호출 없음)
- 오류 body는 `{code, message, fieldErrors, retryable?}`다. 문구는 `code`로 고른다. 띠 안 [다시 실행] 지름길은 **`retryable`이 true일 때만** 그린다.
- `retryable`은 서버 자동 재시도가 아니다. 사용자가 나중에 다시 시도해도 되는지를 뜻한다(계약 §7).
- 지름길이 없어도 본래 실행 버튼은 다시 활성이다. 입력값은 유지한다. 오류 띠에 질문·응답 원문을 넣지 않는다.

| HTTP | code | retryable | 띠 | 문구 | 띠 뒤 동작 |
|---|---|---|---|---|---|
| 400 | `VALIDATION_ERROR` | false | warning | "입력을 확인해 주세요." `fieldErrors`가 있으면 해당 입력란 아래에 표시 | 입력 수정 |
| 400 | `AI_INPUT_TOO_LARGE` | false | warning | AI-02: "평가 자료가 요약 가능한 분량(20개 항목·코멘트 합계 12,000자)을 넘어 요약할 수 없습니다." / AI-01·03: "입력이 너무 깁니다." | — |
| 400 | `AI_NO_COMMENTS` | false | neutral | "요약할 코멘트가 없습니다." (AI-02) | — |
| 401 | `UNAUTHORIZED` | — | — | 기존 세션 만료 흐름(design-system §4.4) | — |
| 403 | `FORBIDDEN` | — | — | 기존 권한 없음 패턴(§4.4). AI-01은 비ADMIN에게 패널이 없으므로 직접 호출 때만 | — |
| 404 | `NOT_FOUND` | — | neutral | "평가서를 찾을 수 없습니다." (AI-02. 권한 없음과 없는 ID를 구분하지 않는다) | — |
| 409 | `AI_EVALUATION_NOT_FINALIZED` | false | warning | "최종 확정된 평가서만 요약할 수 있습니다." | 평가서 재조회. FINALIZED가 아니면 패널이 사라진다 |
| 429 | `AI_BUSY` | true | warning | "다른 AI 요청을 처리하고 있습니다. 끝난 뒤 다시 실행해 주세요." | [다시 실행] |
| 429 | `AI_RATE_LIMITED` | true | warning | "AI 기능은 1분에 10회까지 실행할 수 있습니다. 잠시 후 다시 실행해 주세요." 남은 초는 표시하지 않는다(계약에 헤더 없음) | [다시 실행] |
| 502 | `AI_PROVIDER_ERROR` | true | danger | "AI 제공자와 통신하지 못했습니다." | [다시 실행] |
| 502 | `AI_PROVIDER_REJECTED` | false | danger | "AI 제공자가 요청을 거절했습니다. 관리자에게 제공자 설정 확인을 요청해 주세요." | — |
| 502 | `AI_INVALID_OUTPUT` | true | danger | "AI 응답 형식이 올바르지 않아 결과를 표시하지 않았습니다." | [다시 실행] |
| 503 | `AI_NOT_CONFIGURED` | false | danger | "AI 제공자 설정이 완료되지 않아 실행할 수 없습니다." | — |
| 503 | `AI_DISABLED` | false | neutral | "이 기능은 현재 꺼져 있습니다." | 설정 재조회 → §1.3 꺼짐 상태 |
| 504 | `AI_TIMEOUT` | true | danger | "AI 응답 시간이 초과되었습니다. 제공자 쪽 처리는 계속되었을 수 있습니다." | [다시 실행] |
| 500 | `INTERNAL_ERROR` 등 | 없음 | danger | "서버 오류로 결과를 표시하지 못했습니다." | — (`〈확인 C-04〉`) |
| — | 네트워크 끊김 | — | danger | "서버에 연결하지 못했습니다." | [다시 실행] |

- 모르는 `code`가 오면 같은 HTTP 상태 줄의 일반 문구를 쓴다. 지름길은 `retryable`에 따른다.
- 502 셋은 화면에서 같은 danger 띠로 보이지만 문구로 구분한다. 제공자가 낸 429는 서버가 502 `AI_PROVIDER_ERROR`로 바꿔 준다. 따라서 화면의 429 문구는 사용자 제한에만 쓴다.

## 3. AI-01 사원 목록 자연어 필터 제안 (`POST /ai/employee-search`, ADMIN)

- 위치: 관리 > 사원 관리 목록. 기존 필터 줄 바로 위에 둔다.
- 성격: AI는 **필터 값만 제안**한다. 서버는 검색하지 않는다. 사용자가 [제안 적용]을 누르면 기존 `GET /employees`에 허용 필터만 넘긴다. 그 API가 권한을 다시 검사한다.
- 권한: ADMIN만 보인다. EMPLOYEE에게는 패널을 그리지 않는다(서버 403, 제공자 호출 없음).
- 요청 `{question}`. 응답 `result{status, filters, message}`이고 `status`는 `OK` | `AMBIGUOUS` | `UNSUPPORTED`.
- **지원 필터는 기존 5개뿐이다.**
  - `keyword`: 이름·사번·이메일 부분 검색, 1~100자.
  - `departmentId`: 부서.
  - `positionId`: **직급**. 직책이 아니다.
  - `status`: `ACTIVE`·`ON_LEAVE`·`RETIRED`.
  - `sort`: `employeeNo`|`name`|`hireDate` × `asc`|`desc`.
  - 직책과 입사일 범위 요구는 `UNSUPPORTED`이고 화면에 그 흐름이 없다.

### 3.1 배치 (데스크톱, 기본 접힘)
```
사원 관리                               [내보내기 ▾] [가져오기] [+ 사원 등록]
▸ 자연어로 필터 제안 (AI)                                   ← 펼침 버튼
[검색어      ] [부서 ▾] [직급 ▾] [상태 ▾] [정렬 ▾]  [초기화]    ← 기존 필터
```
펼친 상태:
```
▾ 자연어로 필터 제안 (AI)
┌ AI 실행 안내 (§1, AI-01 전송 문구) ──────────────────────────┐
└───────────────────────────────────────────────────────────┘
질문  ┌───────────────────────────────────────────────┐
      │ 예: 재직 중인 개발 부서 사원을 이름순으로            │
      └───────────────────────────────────────────────┘ 0/500
      제안할 수 있는 조건: 검색어(이름·사번·이메일) · 부서 · 직급 · 상태 · 정렬(사번·이름·입사일)
      직책과 입사일 범위 조건은 지원하지 않습니다.
                                 Ctrl+Enter로 실행   [AI로 필터 제안]
```
- 펼쳐도 AI POST를 보내지 않는다. `GET /ai/config`는 펼칠 때 1회 조회한다.
- 글자 수는 `value.trim().length`로 센다. JS 문자열 길이는 UTF-16 단위라 계약 §6의 Java `String.length`와 같다. 1~500이 아니면 실행 버튼을 비활성으로 둔다(서버 400이 최종 판정이다).
- placeholder는 예시이고 라벨 "질문"은 따로 둔다.

### 3.2 `OK` — 제안 비교표
```
┌ AI 생성 결과 ─────────────────────── [Mock · 실제 추론 아님] ┐
│ 필터 제안                                                  │
│ {message}                                     ← 서버 문장 그대로 │
│  조건      현재              적용 후                [ ]       │
│  검색어    —                 —                              │ muted
│  부서      전체              개발팀                 변경       │
│  직급      전체              전체                           │ muted
│  상태      기본(퇴사 제외)     재직                  변경       │
│  정렬      사번 오름차순        이름 오름차순          변경       │
│ ── meta (§2.2) ──                                          │
│                                     [닫기]   [제안 적용]      │
└──────────────────────────────────────────────────────────┘
```
- 행은 항상 5개 조건 전부다. 바뀌는 행은 "적용 후" 칸을 굵게 하고 글자 배지 "변경"(neutral)을 단다. 색만으로 표시하지 않는다.
- 값 표기:
  - 부서·직급은 화면이 가진 현재 선택지 목록에서 ID로 이름을 찾아 쓴다.
    - 서버는 카탈로그에 있는 ID만 돌려준다. 어긋나면 502 `AI_INVALID_OUTPUT`이다.
    - 그래도 화면 선택지가 낡아 이름을 못 찾으면, 그 행에 warning 글자 "현재 선택지에 없는 값입니다. 목록을 새로 고친 뒤 다시 실행해 주세요."를 붙이고 [제안 적용]을 비활성으로 둔다. 비슷한 값으로 대신 넣지 않는다.
  - `status`는 ACTIVE→재직, ON_LEAVE→휴직, RETIRED→퇴사로 표기한다. 생략되면 "기본(퇴사 제외)"이다. 계약상 생략 시 기존 기본값을 유지한다.
  - `sort`는 `name,asc`→"이름 오름차순"처럼 바꾼다. 생략되면 기존 목록의 기본 정렬 이름을 쓴다.
  - `keyword`는 따옴표로 감싸 일반 텍스트로 쓴다. 생략되면 "—"다.
- **적용 = 교체 (C-01 설계 검토 승인 확정)**: 제안에 없는 조건은 적용하지 않는다(계약 "생략된 조건은 적용하지 않는다", 서버는 `filters`에 있는 허용 필터만 전달).
  - 그래서 적용하면 필터 줄 전체를 `filters` 값으로 맞추고, 빠진 조건은 기본값(전체·기본 정렬)으로 되돌린다.
  - 비교표의 "현재 → 적용 후"가 이 결과를 그대로 보여 준다. 기존 필터를 남겨 두고 덧붙이는 방식은 쓰지 않는다(`〈확인 C-01〉`).

### 3.3 명시 확인 적용
- [제안 적용]을 눌러야만 필터 컨트롤 값이 바뀌고 `GET /employees`를 다시 부른다(page 0). 부르는 값은 화면 필터 값이며 그것이 곧 `filters` 값이다. page·size는 기존 목록 규칙을 따른다.
- 적용 직후 필터 줄 위에 info 띠를 둔다. 문구는 "AI 제안 필터를 적용했습니다. 필터는 직접 바꿀 수 있습니다."이고 [이전 필터로 되돌리기]와 닫기 버튼이 함께 있다.
  - 되돌리기는 적용 직전 값 1단계만 화면 메모리에 둔다. 저장하지 않는다.
  - 사용자가 필터를 직접 바꾸면 이 띠는 사라진다.
- 적용 뒤 결과 카드는 한 줄 요약 "제안 적용됨 · 변경 3개"로 접힌다.
- 적용 결과가 0명이면 기존 빈 결과 패턴(design-system §4.2)을 그대로 쓰고 [이전 필터로 되돌리기]를 함께 둔다.

### 3.4 `AMBIGUOUS` · `UNSUPPORTED`
| status | 카드 본문 | 버튼 |
|---|---|---|
| `AMBIGUOUS` | 소제목 "조건을 확인해 주세요" + `message`(예: "어떤 부서를 의미하는지 부서 이름을 구체적으로 입력해 주세요.") | 적용 없음. 질문 수정 후 다시 실행 |
| `UNSUPPORTED` | 소제목 "필터로 바꿀 수 없는 질문입니다" + `message`(예: "직책과 입사일 범위는 현재 필터 제안에서 지원하지 않습니다.") + 고정 글자 "제안할 수 있는 조건: 검색어 · 부서 · 직급 · 상태 · 정렬" | 적용 없음 |

- 두 상태 모두 `filters`가 `{}`다. 비교표를 그리지 않는다. 부분 조건을 조용히 적용하는 흐름도 없다.
- 오류가 아니므로 결과 카드 안에 neutral(AMBIGUOUS는 warning 글자)로 그리고 danger를 쓰지 않는다. 자동 재실행도 없다.
- 질문은 유지하고 포커스를 입력란으로 돌린다.
- 결과 낡음: 결과가 나온 뒤 질문을 고치거나 필터를 직접 바꾸면 [제안 적용]을 비활성으로 둔다. "현재" 열이 실제 필터와 달라졌기 때문이다.

### 3.5 모바일 (390)
- 펼침 버튼은 모바일 필터 접기 위에 전체 폭으로 둔다.
- 비교표는 바뀌는 조건만 카드로 보인다. 예: "부서 · 전체 → 개발팀 [변경]". 아래에 "나머지 조건은 기본값으로 바뀝니다 (2개)"를 펼치기로 둔다. 화살표는 글자 "→"로 쓰고 aria-label은 "전체에서 개발팀으로"처럼 읽힌다.
- [제안 적용]은 전체 폭 primary로, [닫기]는 그 아래 secondary로 둔다.

## 4. AI-02 확정 평가 코멘트 요약 (`POST /ai/evaluation-summary`)

- 위치: 평가 결과 화면(phase3b-screens §8.9). 평가서가 **FINALIZED일 때만** 패널이 있다. 공개 전·미완료 화면에는 패널, 자리, 비활성 버튼을 모두 그리지 않는다(design-system §11.8).
- 볼 수 있는 사람: 평가서 본인과 배정 평가자.
  - 관계없는 ADMIN에게는 패널을 그리지 않는다. 서버도 404를 준다.
  - 화면은 평가서 조회 결과로 본인·배정 평가자 여부를 판단하고, 서버가 호출마다 다시 검사한다.
- **요청은 `{evaluationId}` 하나뿐이다.** 화면은 코멘트·점수·이름을 보내지 않는다. 서버가 허용된 코멘트를 직접 읽는다.
- 응답 `result{summary}`. `summary`는 1~2000자 일반 텍스트다.

### 4.1 배치 (데스크톱)
```
합성 2026 하반기 · 결과   [최종 확정]
┌ 최종 결과 ─────────────────────────┐   ← 기존 §8.9 그대로(서버 확정값)
│ 등급 [S]           최종 점수 4.50      │
└───────────────────────────────────┘
항목       관리자 점수   관리자 코멘트      자기평가(참고)   ← 원문 그대로
…
──────────────────────────────────────────────────────
▸ AI 코멘트 요약 (참고용 · 읽기 전용)                     ← 펼침, 기본 접힘
┌ AI 실행 안내 (§1, AI-02 전송 문구) ─────────────────┐
└──────────────────────────────────────────────────┘
                                         [AI로 요약 만들기]
┌ AI 생성 결과 ────────────────── [Mock · 실제 추론 아님] ┐
│ 자기평가·관리자 코멘트 요약                                │
│ {summary}                                            │
│ ⓘ 점수와 등급은 위 확정 결과가 기준입니다. 요약은 평가 결과를    │
│   바꾸지 않으며 저장되지 않습니다. 원문 코멘트를 확인해 주세요.   │
│ ── meta (§2.2) ──                                     │
└──────────────────────────────────────────────────────┘
```
- **분리 규칙**:
  - 원문 코멘트, 점수, 등급 블록은 기존 위치·모양 그대로 둔다. 요약은 구분선 아래 별도 섹션(h2 "AI 코멘트 요약")에만 둔다.
  - 요약 카드 안에서 점수·등급을 배지나 큰 숫자로 다시 그리지 않는다. 계약상 점수·등급은 전송되지 않는다.
  - 원문 표 셀에 요약을 끼워 넣거나 툴팁으로 겹치지 않는다.
- 요약 대상은 자기평가와 관리자 코멘트 양쪽이다(계약 §3 전송 자료). 소제목을 그렇게 쓴다.
- **동작 없음**: 요약 카드에는 저장, 제출, 코멘트에 적용, 붙여 넣기, 공유 버튼이 없다. 있는 버튼은 실행, 요청 취소, 다시 실행(retryable일 때)뿐이다.
- 코멘트가 비어 있을 때: 화면은 미리 판정하지 않고 실행 버튼을 그대로 둔다. 서버가 400 `AI_NO_COMMENTS`를 주면 neutral 글자 "요약할 코멘트가 없습니다."를 보인다. 이 경우 제공자 호출과 분당 횟수 차감은 없다(계약 §6 사전검사).
- 분량 초과는 400 `AI_INPUT_TOO_LARGE`다. 일부만 잘라 요약하지 않는다는 뜻을 문구에 담았다(§2.3).

### 4.2 모바일
- 패널은 기존 §8.9 모바일 카드 뒤, 페이지 맨 아래에 둔다. 기본은 접힘이다.
- `summary` 본문은 16/24로 읽기 폭을 확보한다.

## 5. AI-03 합성 규정 Q&A (`POST /ai/policy-qa`, 모든 인증 사용자)

- 위치: "내 업무 > 규정 Q&A" 신규 메뉴. 라우트 이름은 프론트 결정이다(`〈확인 C-02〉`).
- 근거는 서버의 버전 있는 **고정 합성 규정 문서**뿐이다. 외부 웹, DB, 급여·휴가 원문은 검색하지 않는다.
- 요청 `{question}`(1~500자) 하나다. 대화 이력은 없다. 새 질문을 실행하면 이전 답변을 지운다.
- 응답 `result{status, answer, citations[{documentId, version, sectionId, excerpt}], notice}`. `status`는 `ANSWERED` | `INSUFFICIENT_EVIDENCE`.

### 5.1 배치 (데스크톱)
```
규정 Q&A
ⓘ 가상 회사의 합성 데모 규정이며 실제 회사 규정이나 법률 안내가 아닙니다.    ← info 띠, 닫기 없음
┌ AI 실행 안내 (§1, AI-03 전송 문구) ──────────────────────────┐
└────────────────────────────────────────────────────────────┘
질문 ┌───────────────────────────────────────────────┐
     │ 예: 오전 반차일의 출근 기준은 언제인가요?            │
     └───────────────────────────────────────────────┘ 0/500
                                Ctrl+Enter로 실행  [AI로 답변 찾기]

┌ AI 생성 결과 ─────────────────────── [Mock · 실제 추론 아님] ┐
│ ⓘ {notice}                                   ← 서버 고정 문구 │
│ 답변                                                       │
│ {answer}                                                  │
│                                                          │
│ 근거 (1)                                                   │
│ ┌──────────────────────────────────────────────────────┐ │
│ │ 문서 DEMO-ATTENDANCE · 버전 1.0 · 절 HALF_DAY             │ │ mono
│ │ │ 오전 반차일의 출근 기준은 14:00입니다.                    │ │ blockquote
│ └──────────────────────────────────────────────────────┘ │
│ ⓘ 인용은 해당 문서·버전·절의 원문과 글자 그대로 일치하는지 서버가     │
│   확인했습니다. 답변이 질문에 맞는지와 의미가 정확한지는 보장하지      │
│   않으니 근거 원문을 확인해 주세요.                               │
│ ── meta (§2.2) ──                                          │
└──────────────────────────────────────────────────────────┘
```
- 페이지 머리 info 띠는 실행 전에도 보여야 한다. 그래서 계약 §4의 notice 고정 문구를 쓴다. 결과 카드 안에는 응답의 `notice`를 서버 값 그대로 다시 넣는다. 서버 값이 우선이며, 3B `demoNotice` 패턴과 같다.
- **근거(`citations`, 1~3개)**:
  - 근거 1건이 카드 1장이다. 머리는 "문서 {documentId} · 버전 {version} · 절 {sectionId}"이고 세 값을 `--font-mono`로 쓴다. `sectionId`는 사람용 제목이 아니라 ID이므로 그대로 보인다.
  - `excerpt`(1~300자)는 `<blockquote>` 일반 텍스트로 전부 보인다. 화면이 줄이거나 강조하지 않는다. 300자 상한이라 접기는 두지 않는다.
  - 순서는 서버 순서 그대로다.
- **링크 금지**: 문서ID·절·발췌·답변을 하이퍼링크로 만들지 않는다. 텍스트 안의 URL 문자열도 앵커로 바꾸지 않는다. 규정 원문 보기 화면은 계약에 없으므로 만들지 않는다.

### 5.2 `INSUFFICIENT_EVIDENCE` (답변 불가, `answer=null`, `citations=[]`)
```
┌ AI 생성 결과 ─────────────────────── [Mock · 실제 추론 아님] ┐
│ ⓘ {notice}                                                │
│ 답변할 수 없음                                              │
│ 합성 규정 문서에서 이 질문에 답할 근거를 찾지 못했습니다.            │
│ 질문을 바꾸어 다시 실행하거나 인사 담당자에게 문의해 주세요.         │
│ ── meta ──                                                 │
└──────────────────────────────────────────────────────────┘
```
- `answer`가 null이면 "답변" 영역과 "근거" 영역을 **그리지 않는다**. 빈 칸, "—", "근거 0건" 같은 표시도 하지 않는다. 문구는 화면 고정 문구다.
- 서버는 맞지 않는 인용이나 인용 없는 답변을 이 상태로 바꾸고 모델 답변을 노출하지 않는다. 화면은 그 결과만 그린다.
- 오류가 아니므로 neutral 글자로 쓰고 danger를 쓰지 않는다. 자동 재실행도 없다. 질문은 유지하고 포커스를 입력란으로 돌린다.

### 5.3 모바일
- 합성 규정 info 띠가 첫 블록이다.
- 근거 카드는 전체 폭이다. 머리는 "문서 · 버전" 한 줄과 "절" 한 줄로 나눈다. 긴 ID는 `overflow-wrap: anywhere`로 줄바꿈해 가로 스크롤을 만들지 않는다.

## 7. 접근성 · 키보드

- 결과 영역에 `aria-live="polite"`를 둔다. 알리는 문구는 "결과가 도착했습니다", "답변할 수 없음", "필터로 바꿀 수 없는 질문", "오류: {짧은 제목}"뿐이고 본문은 읽어 주지 않는다. 도착하면 포커스를 결과 카드 h3로 옮긴다(`tabindex="-1"`).
- 질문 textarea에서 Ctrl+Enter(맥 Cmd+Enter)로 실행한다. Enter는 줄바꿈이다. 단축키는 버튼 옆에 글로 적는다.
- Esc로는 요청을 취소하지 않는다. 취소는 버튼으로만 한다. 진행 중에는 포커스를 [요청 취소]로 옮긴다.
- Mock 배지는 글자 배지이고 스크린리더 이름은 "Mock 결과, 실제 추론 아님"이다.
- AI-01 비교표는 `<table>`에 `<th scope>`를 쓴다. "변경"은 글자로 표시한다. AI-03 근거는 `<ol>`이고 항목 머리는 h4, 발췌는 `<blockquote>`다.
- 펼침 패널(AI-01·AI-02)은 `<button aria-expanded aria-controls>`로 만든다.
- 대비·포커스 링은 design-system §1.1·§6 토큰 그대로다. 새 색은 없다.

## 8. 메뉴 반영 (S0 확장)

```
내 업무                     관리 (ADMIN)
 …                          사원 관리   ← AI-01 패널(화면 안)
 내 평가  ← AI-02(결과 화면 안)  …
 규정 Q&A ← 신규(AI-03)          감사 로그 ← AI_INVOKE 라벨(§9)
```
- AI 전용 메뉴 그룹은 만들지 않는다. AI 설정·제공자 관리 화면도 없다(서버 환경 설정).

## 9. 감사 로그 라벨 (계약 §9)

| 값 | 화면 라벨 |
|---|---|
| action `AI_INVOKE` | AI 실행 |
| metadata.feature `AI-01` / `AI-02` / `AI-03` | AI 사원 필터 제안 / AI 평가 코멘트 요약 / AI 규정 Q&A |
| provider · model · promptVersion | 제공자 · 모델 · 프롬프트 버전 (서버 문자열) |
| durationMs | 소요 시간(ms), 정수 그대로 |
| errorCode | 오류 코드 (null이면 "—") |

- `AI_INVOKE`는 대상 필드(`targetType` 등)와 전후 값이 null이다. 대상 열은 "—"로 쓰고, 전후 값 비교 블록(design-system §3.9)은 그리지 않는다.
- 감사에는 질문·결과 원문이 없다. 화면이 다른 곳에서 원문을 찾아 붙이지 않는다.

## 11. v1(계약 전 선행 시안) 대비 변경

- **설계 검토 사전 확정**: AI-01 필터를 기존 5개로 한정했다. 직책·입사일 범위는 `UNSUPPORTED` 안내로 바꿨다. v1 예시 문장에 있던 "입사일 최근 순"은 정렬(`hireDate,desc`)로 허용되지만, 혼동을 피하려고 계약 예시 문장으로 교체했다.
- **고지**: 기능별 enabled 키를 `employeeSearch`·`evaluationSummary`·`policyQa`로 고쳤다. 전송·제외 문구는 계약 §5 표로 확정했다(v1 U-06·U-07). Ollama도 외부 전송 true이고 "클라우드 아님" 표현 규칙을 넣었다. 자유 텍스트 개인정보 안내와 감사 기록 안내를 추가했다.
- **결과**: `meta` 7필드로 메타데이터 줄을 확정했다(U-10). 비스트리밍(U-08), 서버 타임아웃 30초(U-09), 결과 DB 비저장(U-02)이 확정됐다. Mock 자동 대체 금지를 추가했다.
- **오류**: HTTP별 일반 문구를 code 16종 표로 바꿨다(U-03·U-12). `retryable`로 [다시 실행] 지름길을 정한다. 429는 `AI_BUSY`·`AI_RATE_LIMITED`로 나눴고 `Retry-After`는 없다(U-13). 502는 3종, 503은 2종으로 구분했다. 취소 직후 `AI_BUSY` 가능성 안내를 추가했다.
- **AI-01**: `POST /ai/employee-search`, `result{status, filters, message}`를 반영했다(U-14·U-15·U-16). 후보 해석 목록을 없애고 `message`만 쓴다(U-19). 잘못된 ID는 서버 502이고 화면은 선택지가 낡은 경우만 처리한다(U-17). 상태 생략은 "기본(퇴사 제외)"으로 표기하고 비교표는 5개 조건 전부를 보인다.
- **AI-02**: 요청은 `{evaluationId}`만 보낸다(U-21). 권한은 본인·배정 평가자이고 그 외는 404다(U-20). 요약 대상은 자기·관리자 코멘트 양쪽이다(U-22). 코멘트 없음은 화면 사전 판정을 없애고 서버 400 `AI_NO_COMMENTS`로 처리한다(U-23).
- **AI-03**: 모든 인증 사용자(U-24), `POST /ai/policy-qa`(U-25), 단일 질문(U-26)이 확정됐다. 인용 4필드는 `documentId`·`version`·`sectionId`·`excerpt`다(U-27). 원문 조회 API는 없다(U-28). 근거 0건 성공은 없고 서버가 `INSUFFICIENT_EVIDENCE`로 바꾼다(U-29). 답변 불가는 `answer=null`·`citations=[]`라 답변·근거 영역을 그리지 않는다(U-30). 서버 `notice`를 결과 카드에 넣었다. 발췌 300자 상한에 맞춰 접기를 없앴다. 인용 검증 한계 안내를 추가했다.
- **추가**: 감사 로그 `AI_INVOKE` 라벨(§9).
