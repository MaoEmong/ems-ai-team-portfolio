## 0. 공통 원칙 (3A 전 화면)

| 원칙 | 화면 규칙 |
|---|---|
| 도메인 판정은 서버 | 지각·조퇴·미기록·미완료·휴가 적용, 연차 잔여, 신청 가능 여부를 **프론트가 계산하지 않는다**. 서버 응답 값을 그대로 배지·문구로 바꾼다. 화면에서 하는 계산은 "표에 보이는 행 수 세기" 같은 표시 집계뿐이며, 그 경우 "(표에서 센 수)"라고 쓴다 |
| 버튼은 allowedActions만 | 휴가 신청 행의 승인·반려·취소 버튼은 응답 `allowedActions`에 그 동작이 있을 때만 보인다. 없으면 버튼을 숨기고(비활성 표시 아님) 필요한 경우 이유를 글로 쓴다(예: 본인 신청). 출퇴근 버튼은 회의록에 allowedActions가 없으므로 §1.2의 "오늘 기록 상태" 표시 규칙을 따르고, 최종 판정은 서버 409로 받는다 |
| 서버 시각·서울 | 화면에 **기기 시계를 기준처럼 보이게 하지 않는다**(실시간 시계 표시 없음). 시각은 서버가 돌려준 값만 `HH:mm:ss`(KST)로 표시. 날짜 `YYYY-MM-DD (요일)` |
| 처리 후 다시 조회 | 출퇴근·정정·신청·승인·반려·취소 성공 또는 409 후에는 관련 데이터를 다시 조회하고 알림 개수도 즉시 갱신 |
| 사유 노출 | 신청 사유·반려 사유·정정 사유는 알림 목록·미리보기·토스트에 넣지 않는다. 권한 있는 상세(펼침) 화면에서만 텍스트로 표시 |
| 데모 정책 안내 | 연차 관련 화면에 고정 문구: "연차는 포트폴리오용으로 단순화한 데모 규칙으로 계산합니다. 법정 기준 충족 여부는 검증하지 않았습니다." |
| 접근성 | 2단계 체크리스트(design-system §6) 그대로. 배지 글자 필수, 모든 표 caption, 모달 포커스 가둠, 결과는 role=status/alert |

## S0. 메뉴 구조 — "내 업무"와 "관리"

```
┌ 사이드바 ─────────┐
│ EMS 사원관리 시스템  │
│                    │
│ 내 업무             │ ← 그룹 제목(12px/600, sidebar-text, 대문자·영문 아님)
│  출퇴근·근태        │  /my/attendance  (제안 경로)
│  휴가               │  /my/leaves
│  내 정보            │  /me (기존)
│ ────────────────── │
│ 관리               │ ← ADMIN만
│  대시보드           │
│  사원 관리          │
│  근태 관리          │  /admin/attendance
│  휴가 결재          │  /admin/leaves — 대기 건수 API가 없으므로 숫자 표시 없음(확정)
│  부서 관리          │
│  직급 관리          │
│  감사 로그          │
└────────────────────┘
```

- ADMIN도 "내 업무"를 쓴다. ADMIN 첫 화면은 기존대로 대시보드, EMPLOYEE 첫 화면은 기존대로 내 정보(`/me`, 확정).
- 마크업: `<nav aria-label="주 메뉴">` 안에 그룹마다 `<div role="group" aria-labelledby>` + 제목. 활성 표시는 2단계 규칙(aria-current + 왼쪽 흰 막대).
- "휴가 결재" 옆 숫자는 **계약에 대기 건수 API가 있을 때만**. 없으면 표시하지 않는다(목록 조회로 세지 않음 — 페이지 크기에 따라 틀릴 수 있음).
- 메뉴 항목이 9개로 늘어난다. 데스크톱 사이드바는 내부 세로 스크롤 허용(`overflow-y: auto`), 하단 모드 표시는 스크롤 영역 밖 고정.
- 모바일: "메뉴 펼치기"로 여는 목록도 같은 두 그룹. 펼친 목록은 `max-height: calc(100dvh - 상단바)` + 내부 스크롤, 항목 높이 44px, 그룹 제목 포함. 메뉴를 열면 첫 항목으로 포커스, Esc로 닫고 버튼으로 복귀.

### 상단 바 (알림 종 추가)
- 데스크톱: `브레드크럼 …… 이름 [역할 배지] [🔔 알림 3] [로그아웃]`.
- 모바일(2단계 NR-01 구조 유지): 1줄 브레드크럼, 2줄 `이름 [배지] …… [알림 3] [로그아웃]`. 알림 버튼 44×44 이상.
- 종 아이콘은 이미지·아이콘 라이브러리 없이 글자 "알림"을 기본으로 한다. 장식 기호(🔔 또는 SVG)는 `aria-hidden`이고 없어도 된다.

### 1.2 출퇴근 카드 상태 (오늘 기록 기준)

카드는 **`GET /attendance/me/today`**(하루 DTO, §9.1)로 그린다. 이 응답의 `date`가 화면 전체의 "오늘(서버 날짜)" 기준이다(월 표의 오늘 행·예정 판단에도 사용). today는 **주말에도 하루 DTO로 조회**되며 주말 전용 플래그가 없다. 따라서 화면은 주말·출근 가능 여부를 **추정하지 않는다**: 주말에도 `NO_RECORD`면 "출근 전" + [출근하기]를 보여 주고, 누른 결과 409 NOT_A_WORKDAY를 §1.5 문구로 안내한다(안내 후 그 세션 동안 버튼을 숨기지 않고 서버 응답을 계속 따른다).

| 상태 | 확정 필드 조건 |
|---|---|
| 출근 전 | `status = NO_RECORD` |
| 근무 중 | `status = INCOMPLETE` (오늘이므로 미완료가 아니라 근무 중으로 표시) |
| 퇴근 완료 | `status = COMPLETE` |
| 휴가일 | `status = LEAVE` — 종일 연차·병가, **또는 오전·오후 반차가 모두 승인된 날**. 종류는 `leaves[]`의 모든 항목을 배지로(예: `[오전 반차][오후 반차]`) |
| 반차일 | `status`가 LEAVE가 아니고 `leaves[]`에 HALF_AM 또는 HALF_PM이 있음 |
| 휴가 없음 | `leaves = []` |
| 판정 배지 | `late`, `earlyLeave` |
| 적용 기준 | `expectedStart`, `expectedEnd` (HH:mm:ss → 화면은 HH:mm) |
| 정정됨 | `corrected = true` |

| 상태 | 조건(서버 값) | 표시 | 버튼 |
|---|---|---|---|
| 출근 전 | 오늘 기록 null | [출근 전] neutral, "아직 출근 기록이 없습니다." | [출근하기] primary |
| 근무 중 | 출근 있음, 퇴근 없음 | [근무 중] info, 출근 시각 + 서버 판정 배지 | [퇴근하기] primary |
| 퇴근 완료 | 출근·퇴근 있음 | [퇴근 완료] success, 두 시각 + 판정 배지 | 없음. "오늘 기록이 끝났습니다." |
| 휴가일 | `status = LEAVE` | [휴가] info + `leaves[]` 종류 배지 | 없음. "승인된 휴가일이라 출근을 기록하지 않습니다." |
| 반차일 | 반차 정보 있음 | 위 상태 + [오전 반차]/[오후 반차] 배지, 적용 기준 14:00 강조(600) | 출근 전/근무 중 규칙 그대로 |
| (주말) | 별도 상태 없음 — 서버 DTO 그대로(대개 NO_RECORD) | 출근 전과 동일 | [출근하기] 노출, 409 NOT_A_WORKDAY는 §1.5 안내 |
| 기록 불가(휴직·입사 전) | 서버가 409 EMPLOYEE_NOT_ACTIVE 등을 반환한 뒤 | 카드 안 neutral 띠로 서버 사유 | 숨김 |

- 버튼 노출은 "오늘 기록 상태"로 고르지만 **판정은 서버**다. 누른 결과 409면 §1.5 문구 + 카드·표 재조회.
- 버튼 진행 중: `출근 기록 중…`/`퇴근 기록 중…`, 중복 클릭 방지. 성공 시 카드 안 success 상태 문구 "출근을 기록했습니다 · 09:03:12 (서버 시각)" (`role=status`) — 시각은 응답 값.
- 퇴근 버튼 근처에 확인 대화상자는 두지 않는다(한 번에 하나, 되돌림은 관리자 정정). 단, 출근 직후 1분 안 퇴근처럼 실수 가능성이 큰 경우를 막는 클라이언트 규칙은 만들지 않는다(정책 아님).
- 카드에 기기 시계·"지금 지각입니다" 같은 예측 문구 없음.

### 1.3 판정 배지 (design-system §10.3)

| 배지 | 조건(서버 값) | 색 묶음 | 비고 |
|---|---|---|---|
| 정상 | 출근·퇴근 있고 지각·조퇴 모두 거짓 | success | |
| 지각 | 지각 참 | warning | 조퇴와 **동시에** 표시 가능 |
| 조퇴 | 조퇴 참 | warning | 지각과 동시에 표시 가능. 두 배지는 순서 고정: 지각 → 조퇴 |
| 미완료 | 출근 있음, 퇴근 없음 | danger(옅은) | 오늘 근무 중인 행도 미완료로 보이면 오해 → **오늘 행은 "근무 중"(info)** 로 표시하고, 지난 날짜만 미완료. 이 구분은 서버 값(날짜)과 오늘 날짜(서버 기준 날짜) 비교로 표시만 바꾼다 |
| 미기록 | 지난 근무일, 기록 null | neutral | "결근"이라고 쓰지 않는다(자동 결근 없음) |
| 휴가 | 승인된 종일 휴가일 | info | 종류는 비고 열 |
| 예정 | 오늘 이후 근무일, 기록 null | 배지 없음, muted "—" | |

- 지각만 있고 퇴근이 없으면 `[지각][미완료]`처럼 판정 배지와 기록 상태 배지가 함께 나올 수 있다.
- 확정 필드 매핑(월 응답 `days[]`의 하루 DTO):

| 화면 배지 | 조건 |
|---|---|
| 정상 | `status = COMPLETE` 이고 `late`·`earlyLeave` 모두 false |
| 지각 / 조퇴 | `late = true` / `earlyLeave = true` (status와 무관하게 표시) |
| 근무 중 | `status = INCOMPLETE` 이고 `date` = 오늘(today 응답의 date) |
| 미완료 | `status = INCOMPLETE` 이고 `date` < 오늘 |
| 미기록 | `status = NO_RECORD` 이고 `date` < 오늘 |
| (오늘 출근 전) | `status = NO_RECORD` 이고 `date` = 오늘 → 배지 없이 "출근 전" muted |
| 예정 | `status = NO_RECORD` 이고 `date` > 오늘 → "—" |
| 휴가 | `status = LEAVE` (이때 late/earlyLeave는 false) + 비고에 `leaves[]` 각 종류 라벨 |
| 반차 비고 | `leaves[]`에 HALF_AM/HALF_PM이 있으면 비고 배지(두 건이면 둘 다), 적용 기준 `expectedStart`/`expectedEnd` 중 14:00 쪽 굵게 |
| 정정됨 | `corrected = true` |

- 오늘 날짜 비교는 위 표처럼 **today 응답의 `date`** 를 쓴다(기기 날짜 사용 금지). today 조회가 실패하면 근무 중/미완료 구분 없이 "미완료"로 표시하지 말고 "퇴근 기록 없음" 중립 문구를 쓴다.
- 월 응답 `{employeeId, month, days}`: `days` 순서는 서버 순서를 따르되 표는 최신 날짜가 위(내림차순)로 보여 준다. 정렬 방향은 구현 판단(오름차순도 허용)이며 caption에 명시.

### 1.4 표 열과 표시
| 열 | 값 | 규칙 |
|---|---|---|
| 날짜 | 근무일 | `10-16 (금)`, 표 caption에 연월. 오늘 행은 primary-subtle 배경 + "오늘" sr 텍스트 |
| 출근 / 퇴근 | 〈서버 값: 시각〉 | `HH:mm:ss` tabular, 없으면 "—" |
| 판정 | §1.3 배지 | 여러 개면 4px 간격 |
| 적용 기준 | 〈서버 값: 적용한 출근 기준·퇴근 기준〉 | `09:00 / 18:00`. 반차로 14:00이 적용된 쪽은 굵게. 서버가 기준을 보내지 않는 행(휴가·예정)은 "—" |
| 비고 | `leaves[]`(빈 배열이면 없음), `corrected` | `[연차]` `[오전 반차]` `[오후 반차]` `[병가]` info 배지, `[정정됨]` neutral 배지 |

- **근무 시간·합계 열을 만들지 않는다**(회의록 범위 제외).

- 입력: `type="time" step="1"`(초 단위, 날짜는 행의 날짜로 고정해 표시만). 라벨에 "(KST)", 도움말에 "서울 시각". 전송은 `{행 날짜}T{HH:mm:ss}+09:00` 오프셋 ISO-8601(확정 계약). 기기 시간대와 무관하게 +09:00을 붙인다.

- 기록 없는 날(미기록) 정정: 제목 "근태 기록 만들기", 현재 기록 블록에 "기록 없음".

- 주말 행은 월 응답에 오지 않는 것이 기본이며, 주말 정정은 서버 409 NOT_A_WORKDAY 문구("주말 날짜는 정정할 수 없습니다.")로 모달 안에 표시.

- 성공: 모달 닫기 → 표 재조회 → 해당 행 success 하이라이트 2초 + `role=status` "2026-10-13 근태를 정정했습니다."
- 확정 버튼 primary(되돌리기는 재정정 가능). 첫 포커스 출근 시각.
- 모바일: 모달 폭 100%-32px, 시각 입력 세로 쌓기, 본문 내부 스크롤(2단계 U-6 규칙).

```
신청자 테스트 사원 3 (EMP003)                         [승인] [반려]  또는  [신청 취소]
┌ 신청 내용 ─────────────────────────────┐
│ 종류 연차   기간 2026-11-02 ~ 11-04   일수 3일 │
```

- 버튼은 `allowedActions`(`APPROVE`·`REJECT`·`CANCEL`)에 있는 것만. 승인·반려·취소 모달은 §3.4 아래·S4와 같다. 처리 후 상세 재조회.

- 사유(신청·반려)는 이 화면에서만 텍스트 노드로 표시.
- 모바일: 머리 버튼은 제목 아래 전체 폭 세로 쌓기, 두 정보 블록은 dl 1열.
- 신청 취소 확인 모달(440px): "2026-11-02 ~ 11-04 연차 신청을 취소합니다. 예약(또는 사용)된 연차가 되돌아갑니다." [닫기] [신청 취소](danger-solid). 승인된 신청이면 "승인된 휴가는 시작일 전날까지만 취소할 수 있습니다." 추가.
- 정렬은 서버 순서 그대로.

### 3.5 오류·충돌 문구
| 코드 | 문구 |
|---|---|
| LEAVE_OVERLAP | 이미 신청했거나 승인된 휴가와 날짜가 겹칩니다. 같은 날 오전·오후 반차는 함께 신청할 수 있습니다. |

| EMPLOYEE_NOT_ACTIVE (신청 시) | 재직 중이 아니거나 입사일 전이라 휴가를 신청할 수 없습니다. |
| LEAVE_RECORDS_EXIST (사원 수정 화면, 2단계 화면) | 휴가 기록이 있는 사원은 입사일을 바꿀 수 없습니다. |
| 400 근무일 없음 등 VALIDATION_ERROR | 서버 fieldErrors를 필드 아래, 없으면 상단 |
| EMPLOYEE_NOT_ACTIVE 등 | 서버 message |

### 3.6 모바일
- 잔여 카드 2×2(사용 가능이 첫 칸), 산정 기간 줄은 카드 위.
- [+ 휴가 신청] 전체 폭.

```

상태 [결재 대기 ▾]  사원 [선택 ▾]  [조회]
```

- 상태 필터 기본값 "결재 대기"(PENDING). 전체/대기/승인/반려/취소.

## S5. 알림 (종 + 패널)

### 5.1 종 버튼
- `[알림 3]` — 읽지 않은 수 배지(danger-strong 배경 흰 글자 12px, 99 초과 "99+"). 0이면 숫자 배지 없음.
- 접근 이름: `aria-label="알림, 읽지 않음 3건"`, `aria-expanded`, `aria-controls`.
- 개수 변화 낭독: 증가했을 때만 별도 `aria-live="polite"` 영역에 "새 알림 1건"(폴링마다 반복 낭독 금지).

### 5.2 패널
```
데스크톱: 종 아래 드롭다운 360×최대 480px      모바일: 상단 바 아래 전체 폭 시트(최대 70dvh)
┌ 알림 ─────────────── [모두 읽음] ┐
│ ● 휴가 신청이 승인되었습니다          │ unread: 점 + 600 굵기
│   연차 · 2026-11-02 ~ 11-04         │ 표시 문구(서버 값)
│   2026-10-16 14:02                 │ muted, KST
│ ─────────────────────────────── │
│   근태 기록이 정정되었습니다          │ read: 400 굵기, 점 없음
│   2026-10-13                        │
│   2026-10-16 10:11                 │
│ ─────────────────────────────── │
│ [더 보기]                           │ 다음 페이지
└─────────────────────────────────┘
```
확정 항목 필드: `id, type, targetType(LEAVE|ATTENDANCE), targetId, targetDate, message, read, createdAt`.

| 유형 | 제목(프론트 라벨) | 이동 |
|---|---|---|
| LEAVE_REQUESTED | 새 휴가 신청이 있습니다 | `/leaves/{targetId}` 휴가 상세 |
| LEAVE_APPROVED | 휴가 신청이 승인되었습니다 | `/leaves/{targetId}` |
| LEAVE_REJECTED | 휴가 신청이 반려되었습니다 | `/leaves/{targetId}` (반려 사유는 상세에서) |
| LEAVE_CANCELLED | 휴가 신청이 취소되었습니다 | `/leaves/{targetId}` |
| ATTENDANCE_CORRECTED | 근태 기록이 정정되었습니다 | `/my/attendance?month={targetDate의 YYYY-MM}` (해당 날짜 행 강조) |
| 그 밖 / 알 수 없는 type | `message` 그대로 | targetType 규칙으로 이동, 둘 다 없으면 이동 없음 |

- 이동 규칙은 type이 아니라 **`targetType`** 으로 정한다(LEAVE → 휴가 상세, ATTENDANCE → 내 근태 해당 월). 제목은 type 라벨, 둘째 줄은 `message`, 셋째 줄 `createdAt`(KST `YYYY-MM-DD HH:mm`). 읽지 않음 표시는 `read = false`.
- 둘째 줄은 서버가 준 최소 표시 문구(종류·날짜)만. **사유·반려 사유 미리보기 없음.** 서버 문구 자체에 사유가 없다는 전제이며 프론트가 상세 API를 미리 불러와 붙이지 않는다.
- 응답: 개수 `{count}`, 단건 읽음 204(본문 없음), 모두 읽음 `{updatedCount}`. 모두 읽음 성공 시 `updatedCount > 0`이면 `role=status` "알림 {updatedCount}건을 읽음 처리했습니다.", 0이면 "읽음 처리할 알림이 없었습니다."
- 항목 클릭: 단건 읽음 `POST /notifications/{id}/read` → 이동 → 패널 닫힘. 읽음 실패해도 이동은 진행(다음 폴링에 반영). 이동 대상 신청이 권한 밖이거나 없어졌으면 그 화면의 404/403 문구.
- [모두 읽음]: 현재 불러온 목록의 **가장 큰 id를 upToId로** 전송. 성공 후 목록·개수 재조회. 그 뒤 도착한 알림은 계속 읽지 않음으로 남는다(안내 문구 불필요).
- 필터 토글(선택): "읽지 않은 알림만" (`unreadOnly`).
- 빈 상태: "새 알림이 없습니다." / unreadOnly일 때 "읽지 않은 알림이 없습니다."
- 오류: 패널 안 "알림을 불러오지 못했습니다. [다시 시도]". 종 배지는 직전 값 유지(배경 폴링 실패는 표시하지 않음).
- 키보드: 패널 열면 첫 항목(또는 "모두 읽음")으로 포커스, Esc·바깥 클릭으로 닫고 종으로 포커스 복귀. 항목은 `<a>`/`<button>` 목록(`<ul>`), 화살표 이동은 선택.

### 5.3 폴링 표시 규칙
- 화면이 보일 때(`document.visibilityState === "visible"`) 30초마다 unread-count, 화면 복귀·업무 처리 직후 즉시. 패널이 열려 있으면 목록도 갱신하되 스크롤 위치 유지.
- 배경 갱신 중 로딩 표시 없음(깜박임 금지).
- 로그아웃·계정 변경 시 폴링 중지 + 배지·목록 즉시 비움. 이전 계정의 늦은 응답은 화면에 반영하지 않는다.

### 9.1 근태
- `GET /attendance/me/today` 추가 → 하루 DTO.
- 하루 DTO: `date, checkIn, checkOut, late, earlyLeave, status(NO_RECORD|INCOMPLETE|COMPLETE|LEAVE), expectedStart, expectedEnd(HH:mm:ss), leaves[{id,type}](없으면 []), corrected`. 휴가일(종일 또는 양쪽 반차)은 status LEAVE이며 late/earlyLeave=false.
- today는 주말에도 하루 DTO로 조회된다(주말 플래그 없음).
- 정정 `PUT /attendance/{employeeId}/{date}` `{checkIn(필수), checkOut(선택/null), reason}` — 오프셋 ISO-8601 초 단위.
- 월 응답: `{employeeId, month, days}`.
- 화면 매핑: §1.2 카드 표, §1.3 배지 표. 화면은 HH:mm:ss 중 기준 시각은 HH:mm로 줄여 표시(시각 기록은 초까지).

### 9.2 휴가
- `GET /leaves/{id}` 추가(본인·ADMIN, 403·404) → §3.4A 휴가 상세.
- 항목: `allowedActions(APPROVE|REJECT|CANCEL), days, rejectReason, decidedBy, decidedAt, cancelledBy(SELF|SYSTEM|null)`.
- 잔액: `approverAvailable=false`여도 신청 허용, 안내만(§3.2).
- `GET /leaves/me?status&page&size` 지원.
- 자기 신청 승인·반려 403. 시작일이 지난 PENDING은 allowedActions REJECT만, 승인 시도는 409 `LEAVE_START_PASSED`(반려 허용). 취소: PENDING은 시작일과 무관하게 본인 CANCEL, APPROVED는 시작일 전날까지만 본인 CANCEL(이후 409 `LEAVE_START_PASSED`). 화면은 allowedActions만 따른다(2026-10-16 확정 정책).
- 입사일이 미래이거나 ACTIVE가 아닌 사원의 출퇴근·신청은 409 `EMPLOYEE_NOT_ACTIVE`.

### 9.3 알림
- 항목: `id, type, targetType(LEAVE|ATTENDANCE), targetId, targetDate, message, read, createdAt`.
- 링크: LEAVE → 휴가 상세, ATTENDANCE → 내 근태 해당 월.
- 응답: unread-count `{count}`, 단건 읽음 204, 모두 읽음 `{updatedCount}`.
