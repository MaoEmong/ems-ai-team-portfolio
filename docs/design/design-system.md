- 작성: 프론트엔드팀 UI·UX 디자이너 (Claude 엔진), 2026-10-16
- 근거: `frontend/src` 현행 코드(1단계), 2026-10-16 1단계 종료·2단계 착수 회의록의 확정 계약, `docs/api/phase2-api.md`(추가 확정 사항 포함, 2026-10-16 프론트 담당 전달분 반영)
- 함께 보는 문서: [screens.md](screens.md) (화면별 시안·상태·문구), [mockups.html](mockups.html) (브라우저로 여는 정적 시각 시안)
- 범위: 규칙과 시안만 정한다. 구현·테스트·ADR(0202 디자인 시스템·차트 선택 포함)은 Codex 구현 담당이 정한다. 이 문서는 서버 계약을 바꾸지 않는다.
- 효과 표기 원칙: 이 문서는 "적용 규칙"이다. 개선 효과는 구현 후 `design-review-*.md`의 전후 스크린샷·지적·반영 기록으로만 남긴다.

## 0. 설계 방향

| 원칙 | 의미 | 현행 대비 바꾸는 점 |
|---|---|---|
| 데이터가 주인공 | 장식은 줄이고 숫자·표·상태가 먼저 읽히게 한다 | 큰 제목(28px)·넓은 셀 여백(17px)을 줄여 한 화면 정보량을 늘림 |
| 계층 3단 | 페이지 제목 → 섹션 패널 → 패널 내부 표/폼 | `eyebrow`(영문 대문자 라벨)를 없애고 브레드크럼으로 위치를 표시 |
| 상태는 색 + 글자 | 재직/휴직/퇴사, 성공/실패는 색만으로 구분하지 않는다 | 배지에 항상 한국어 라벨, 실패는 아이콘 문자(!)까지 |
| 위험 동작은 한 번 더 | 퇴사·삭제·발령·가져오기는 대화상자 확인 | 발령·가져오기에 같은 패턴을 적용 |
| 계약을 화면에 드러냄 | 서버 규칙(전부 취소, [from,to), 현재 분포)을 화면 문구로 설명 | 안내 문구 표준을 아래 9절에 고정 |

모든 수치(px)는 현행 `style.css`를 기준으로 조정했다. 새 의존성(폰트·아이콘·차트 라이브러리)은 필수가 아니다.

## 1. 디자인 토큰

구현은 `:root`의 CSS 사용자 정의 속성으로 둔다. 컴포넌트 CSS에는 hex를 직접 쓰지 않고 토큰 이름만 쓴다. 이번 단계는 **라이트 모드만** 대상으로 한다(다크 모드는 범위 외. 토큰 이름을 역할 기준으로 지어 나중에 값만 바꿔 추가할 수 있게 한다).

### 1.2 글꼴

```css
--font-sans: "Pretendard", "Noto Sans KR", "Apple SD Gothic Neo",
             "Malgun Gothic", "Segoe UI", system-ui, sans-serif;
--font-mono: ui-monospace, "Cascadia Mono", "D2Coding", Consolas, monospace;
```

- 웹 폰트를 새로 내려받지 않는다. 설치되어 있으면 쓰고, 없으면 OS 기본 한글 글꼴(Windows 맑은 고딕)로 떨어진다. 검수 스크린샷은 대체 글꼴 기준으로 본다.
- 숫자 열·KPI·날짜에는 `font-variant-numeric: tabular-nums`를 준다(자릿수 정렬).
- 사번·감사 로그 전후 값의 키 이름에만 `--font-mono`.

| `--text-display` | 32/40 | 700 | 대시보드 KPI 숫자 |
| `--text-h1` | 22/30 | 700 | 페이지 제목 (현행 28 → 22) |

| 이름 | 폭 | 레이아웃 |

## 2. 레이아웃 골격 (앱 셸)

```
┌──────────┬──────────────────────────────────────────────┐
│ EMS      │ 홈 / 사원 관리                     홍길동 관리자 [로그아웃] │ ← 상단 바 60px
│ 사원관리  ├──────────────────────────────────────────────┤
│          │ 사원 관리                          [내보내기▾][가져오기][+ 사원 등록] │ ← 페이지 머리
│ ▣ 대시보드│ 조직의 구성원과 재직 현황                          │
│ ▣ 사원 관리│ ┌ 패널 ─────────────────────────────────────┐ │
│ ▣ 부서 관리│ │ 필터 줄                                    │ │
│ ▣ 직급 관리│ │ 표                                        │ │
│ ▣ 감사 로그│ │ 페이지 이동                                │ │
│ ─────    │ └───────────────────────────────────────────┘ │
│ ▣ 내 정보 │                                              │
│ 실제 API  │                                              │
└──────────┴──────────────────────────────────────────────┘
```

- **메뉴 순서(관리자)**: 대시보드 / 사원 관리 / 부서 관리 / 직급 관리 / 감사 로그 / (구분선) / 내 정보. **일반 사원**: 내 정보만.
- 활성 메뉴: `aria-current="page"`(NavLink 기본) + 배경 `--color-sidebar-active` + 왼쪽 3px 흰 막대. 색만으로 구분하지 않는다.
- 상단 바 왼쪽: 브레드크럼(`홈 / 사원 관리 / 홍길동`). 오른쪽: 이름 + 역할 배지(neutral) + 로그아웃(보조 버튼).
- 사이드바 하단 모드 표시: "목업 모드"(info 배지) / "실제 API". 문구는 유지.
- 첫 화면: `/` → ADMIN `/dashboard`, EMPLOYEE `/me` (로그인 성공 이동도 동일).
- 페이지 머리: 왼쪽 h1 + 한 줄 설명(text-secondary), 오른쪽 동작 버튼. 주요 버튼(primary)은 페이지당 1개.
- 건너뛰기 링크: 셸 맨 앞에 "본문으로 건너뛰기"(포커스 시에만 보임) → `<main id="main" tabindex="-1">`.
- 경로 이동 시 문서 제목 `"{페이지} · EMS"` 갱신, 포커스를 h1로 옮긴다.

## 3. 컴포넌트 규칙

### 3.1 버튼

| 종류 | 모양 | 쓰임 |
|---|---|---|
| primary | 채움 `--color-primary`, 흰 글자 | 페이지당 1개 주 동작(사원 등록, 저장, 로그인, 발령 등록 확정) |
| secondary | 흰 배경, `--color-border-input` 테두리, text 색 | 일반 동작(수정, 취소, 내보내기, 다시 시도) |
| danger | 흰 배경, danger 글자·테두리 | 위험 동작의 진입(퇴사 처리, 삭제) |
| danger-solid | `#b42332` 채움, 흰 글자 | 위험 동작 확인 대화상자의 최종 버튼 |
| ghost | 테두리 없음, primary 글자 | 표 안 보조 링크형 동작, "필터 초기화" |

- 높이 40px(sm 32px), 좌우 여백 16px(sm 12px), 글자 14px/600.
- 진행 중: 라벨을 동사형 진행형으로 바꾸고(`저장 중…`, `업로드 중…`) `disabled` + `aria-busy="true"`. 버튼 폭이 흔들리지 않게 `min-width` 유지.
- 비활성: 불투명도 0.5 대신 `--color-surface-subtle` 배경 + `--color-text-muted` 글자(대비 유지). 이유를 알 수 없는 비활성은 피하고, 비활성이면 옆에 이유를 한 줄로 쓴다(예: 퇴사자 → "퇴사한 사원은 발령할 수 없습니다").
- 아이콘만 있는 버튼은 만들지 않는다(아이콘 라이브러리 없음). 필요하면 글자 + 장식 문자(`+`, `↓`)이며 장식 문자는 `aria-hidden`.
- 표 행의 같은 이름 버튼(수정/삭제)은 현행처럼 `sr-only`로 대상 이름을 붙인다.

### 3.2 폼

- 라벨은 입력 위, 13px/600, 필수는 라벨 뒤 `*`(`aria-hidden`) + 입력에 `required`/`aria-required`. 폼 상단에 "* 표시는 필수 항목입니다" 캡션 1회.
- 도움말: 라벨 아래 캡션(12px, muted), `aria-describedby`로 연결. 오류가 있으면 오류 id도 함께 연결.
- 오류: 입력 테두리 danger + 아래 danger 글자 `! 사유`. 글자 앞 "!"로 색 외 단서를 준다. 제출 실패 시 폼 상단 오류 요약(4.3)으로 포커스를 옮기고, 요약의 각 항목은 해당 입력으로 가는 링크.
- 읽기 전용 필드(사원 수정의 부서·직급): 입력 상자 대신 **값 + 잠금 안내** 블록. 배경 `--color-surface-subtle`, 테두리 점선 `--color-border`, 값은 text 색. 아래 캡션 "부서·직급은 발령 등록으로만 바꿀 수 있습니다." + 상세 화면의 발령 등록으로 가는 링크. `<select disabled>`를 쓰지 않는다(값이 흐려지고 전송 여부가 오해됨). 이 필드는 **요청 본문에 넣지 않는다**.
- 날짜 입력: `type="date"`, 최소·최대를 계약 규칙으로 지정(발령 `min = max(입사일, 마지막 발령일)`, `max = 오늘(서울)`). 안내 캡션으로 규칙을 글자로도 적는다.
- 그리드: 데스크톱 2열, 모바일 1열. 폼 하단 동작 줄은 오른쪽 정렬(취소 → 저장), 모바일은 전체 폭 세로 쌓기(저장이 위).
- 사번 등 식별자 입력: `--font-mono` 미적용(입력 중 혼동 방지), 표시할 때만 tabular.

### 3.3 표

- 머리글: 배경 surface-subtle, 12px/600 muted, 높이 40px. `<th scope="col">`.
- 셀: 13px, 세로 여백 12px(현행 17px → 12px), 좌우 16px. 행 구분선 `--color-border`.
- 숫자 열(인원, 건수, 행 번호)과 날짜 열은 오른쪽/가운데가 아닌 **숫자 오른쪽 정렬, 날짜 왼쪽 정렬 + tabular-nums**.
- 첫 식별 열(이름)은 링크(primary, 600). 행 전체 클릭은 쓰지 않는다(키보드·보조기기 일관성).
- hover: 행 배경 `#f9fbfd`. 선택·강조 행: primary-subtle.
- 정렬 가능한 열을 별도로 만들지 않는다(정렬은 현행처럼 필터 줄의 정렬 선택). 
- 표 위 "결과 요약 줄": `총 128명 · 재직·휴직 · 부서: 개발팀` 처럼 적용된 조건을 글로 보여 준다(`aria-live="polite"`). 내보내기 범위 설명과 같은 문구를 재사용한다.
- 페이지 이동: 요약 줄 반대편이 아닌 표 아래 오른쪽. `이전 | 3 / 12 | 다음` + 페이지 크기. 모바일은 요약 줄 1행, 이동 1행.
- 캡션: 각 표에 `<caption>`(시각적으로 숨겨도 됨)으로 표 이름을 준다.

### 3.4 배지

| 배지 | 묶음 | 라벨 |
|---|---|---|
| 재직 ACTIVE | success | `재직` |
| 휴직 ON_LEAVE | warning | `휴직` |
| 퇴사 RETIRED | neutral | `퇴사` |
| 역할 ADMIN / EMPLOYEE | info / neutral | `관리자` / `일반 사원` |
| 감사 성공 / 실패 | success / danger | `성공` / `! 실패` |
| 감사 대상 유형 | neutral | `사원`·`부서`·`직급`·`해당 없음` |
| 목업 모드 | info | `목업 모드` |

- 12px/600, 높이 22px, 좌우 8px, pill. 앞에 6px 점(색)을 둘 수 있으나 라벨 글자는 항상 있다.
- 현행 CSS 클래스 `.ON_LEAVE`/`.RETIRED`처럼 상태값을 그대로 전역 클래스로 쓰지 말고 `badge--warning` 같은 의미 클래스로 바꾼다(전역 충돌 방지).

### 3.5 대화상자(모달)

- 현행 `Modal` 컴포넌트의 포커스 가둠·Esc·포커스 복귀를 유지한다. 추가 규칙:
  - 폭: 확인형 440px, 입력형(발령 등록) 560px. 모바일은 화면 아래에서 올라오는 시트 대신 **전체 폭 - 32px** 가운데 정렬 유지(구현 단순성), 높이가 넘치면 본문만 스크롤(`max-height: calc(100dvh - 48px)`).
  - 구조: 제목(h2, `aria-labelledby`) → 설명(`aria-describedby`) → 본문 → 하단 동작 줄(오른쪽 정렬: 취소 → 확정).
  - 위험 확인: 확정 버튼은 danger-solid, 첫 포커스는 **취소**(현행 삭제 대화상자 방식) 또는 첫 입력(퇴사일 입력처럼 입력이 있을 때).
  - 진행 중(busy)일 때 Esc·바깥 클릭·취소 비활성, 확정 버튼 `처리 중…`.
  - 바깥(가림막) 클릭으로 닫지 않는다(입력 손실 방지). 닫기는 취소 버튼·Esc로만.
  - 서버 오류는 대화상자 안 상단 오류 알림(4.3)으로 보이고 대화상자는 유지.

### 3.6 알림·안내 띠 (Callout)

| 종류 | 쓰임 | 역할 |
|---|---|---|
| info | 범위 설명(내보내기 범위, 집계 기준일, 전부 취소 규칙) | 정적 텍스트, role 없음 |
| warning | 되돌릴 수 없는 결과 경고 | 정적, 대화상자 설명으로 연결 |
| danger | 요청 실패, 가져오기 전부 취소 결과 | `role="alert"` |
| success | 저장·가져오기 완료 | `role="status"` |

- 모양: 왼쪽 4px 색 막대 + 연한 배경 + 제목(14/600) + 본문(13). 앞에 기호(ⓘ, !, ✓)를 글자로 둔다(`aria-hidden`, 의미는 제목 글자가 전달).
- 성공 알림은 페이지 이동 없이 결과를 알릴 때만(가져오기, 발령 등록 후). 저장 후 상세로 이동하는 기존 흐름은 유지.

### 3.7 KPI 카드(통계 타일)

```
┌────────────────────────┐
│ 재직 인원               │ 13/600 secondary
│ 128 명                  │ 32/700 tabular + 14 단위
│ 재직 118 · 휴직 10       │ 12 muted (보조 구성)
└────────────────────────┘
```

- 숫자 하나 = 카드 하나. 증감 화살표·전월 대비는 계약에 없으므로 **만들지 않는다**(추정 금지).
- 카드는 `<section aria-labelledby>`가 아닌 단순 `<div>` + 라벨 `<p>` + 값 `<p>`로, 전체를 `<dl>`로 묶어도 된다(dt=라벨, dd=값).

### 3.8 차트

**라이브러리**: 필수 아님. 권장은 **의존성 없는 인라인 SVG**(막대 12개×2계열, 가로 막대 N개 수준이라 직접 그리기 충분, 번들 증가 없음). 라이브러리를 도입할지는 구현 담당이 ADR 0202에서 결정하되, 아래 규칙은 어느 방식이든 동일하게 지킨다.

공통 규칙
1. **차트 제목이 의미를 말한다**: "최근 12개월 월별 입사·퇴사 건수", "재직자 현재 부서별 분포". 부제(캡션)에 기준: "기준일 2026-10-16 (Asia/Seoul) · 미래 날짜 제외".
2. **차트마다 같은 데이터의 표를 함께 둔다**. 데스크톱은 차트 아래 "표로 보기" 펼침(`<details>`), 모바일도 동일. 표는 스크린 리더의 기본 경로이며 SVG에는 `role="img"` + `aria-label`로 한 문장 요약(예: "최근 12개월 입사 합계 34건, 퇴사 합계 12건. 자세한 수치는 아래 표")을 준다.
3. 축은 한 개(이중 축 금지). y축은 0부터, 눈금은 정수만(건수·인원): `step = max(1, ceil(최대값/4))`, 축 상한 `= step×4` (시안 mockups.html과 같은 규칙).
4. 막대: 두께 최대 16px, 계열 사이 간격 2px, 월 묶음 사이 여백은 막대 폭 이상. 끝은 위쪽만 4px 둥글게(아래는 기준선에 붙임). 값 0인 달은 막대 없이 기준선만(높이 0, 1px 표시 없음).
5. 격자선은 가로만, `--chart-grid` 1px. 축선 없음(기준선 0만 `--color-border-input`).
6. 범례: 2계열이므로 차트 위 왼쪽에 항상 표시(■ 입사 ■ 퇴사, 글자는 text 색). 계열색만으로 구분하지 않도록 **표와 툴팁에 계열명을 글자로** 넣는다.
7. 직접 라벨: 월별 막대에는 숫자를 모두 달지 않는다. 분포 가로 막대는 막대 끝에 값(인원)을 단다(항목별 비교가 목적이므로).
8. 툴팁(마우스·키보드): 월 묶음 전체를 넓은 투명 영역으로 잡아 hover/focus 시 `2026-05 · 입사 3건 · 퇴사 1건`. 키보드는 차트 영역에 `tabindex="0"` 하나 + 좌우 화살표로 월 이동(구현 부담이 크면 툴팁 생략 가능, **표가 필수 대체 수단**).
9. x축 라벨: `11월`, `12월`, `2026.1`처럼 해가 바뀌는 첫 달에만 연도. 모바일(<720px)에서는 2개월마다 라벨, 막대 폭 축소(최소 6px). 차트 높이 데스크톱 240px, 모바일 200px.
10. 분포 차트(부서·직급)는 **가로 막대**, 단일 계열색 `--chart-bar`, 인원 내림차순(직급은 level 순서를 따름 — 직급은 서열이 의미이므로). 항목이 8개 초과면 상위 7개 + "기타 N개 부서"로 접고, 전체는 표에서 본다.
11. 데이터가 모두 0이면 차트를 그리지 않고 빈 상태(4.2)를 보인다. 일부 0은 정상 표시.

### 3.9 전후 값 비교(감사 로그 전용)

- before/after는 **키-값 표**로 그린다. 열: `항목 | 변경 전 | 변경 후`. 바뀐 항목 행은 왼쪽 막대 + `변경` 배지(info), 같은 값은 기본 접힘("변경 없는 항목 4개 보기").
- 값은 **텍스트 노드로만** 넣는다(`dangerouslySetInnerHTML` 금지, JSON 문자열을 HTML로 해석하지 않음). 객체·배열 값은 `JSON.stringify(v, null, 2)`를 `<pre>`에 텍스트로.
- `null`/없는 쪽은 `해당 없음`(일반 글자 + muted 색, 이탤릭 아님). 생성은 "변경 전" 열 전체가 해당 없음, 삭제는 "변경 후"가 해당 없음.
- 로그인(LOGIN_*)·가져오기(EMPLOYEE_IMPORT)·내보내기(EMPLOYEE_EXPORT)는 before/after가 모두 null이다. 이때 전후 표 대신 한 줄 dl `변경 전 해당 없음 · 변경 후 해당 없음` + 캡션 "이 기록은 개별 값 변경을 담지 않습니다. 부가 정보를 확인하세요." 후 metadata 표. (가져온 사원 각각의 값은 같은 시각의 '사원 등록(출처: 가져오기)' 기록에 있다는 안내를 IMPORT 성공 행에 덧붙인다.)
- 객체 값 `department{id,name}`, `position{id,name,level}`은 `이름` (+ 직급은 `· 정렬 순서 {level}`)으로 한 칸에 표시하고 id는 생략. 비교는 id 기준으로 "변경" 판정.
- **스냅샷 의미 표시**: actor·targetLabel·before/after의 이름은 **기록 당시 값**이다. 상세 펼침 상단 캡션 1회: "이름·부서·직급은 기록 당시 값입니다. 현재 값과 다를 수 있습니다." 행위자·대상 이름에 현재 정보 링크를 걸 때도 이 캡션을 유지한다.
- metadata `filters`(EXPORT): 소표로 `검색어 / 부서 ID / 직급 ID / 재직 상태 / 정렬`을 한국어 라벨로, 값이 없거나 null인 키는 "조건 없음". keyword는 서버가 100자로 잘라 저장하므로 100자인 경우 끝에 caption "(최대 100자까지 저장)". status·sort는 표시 라벨로 변환(예: `employeeNo,asc` → 사번 오름차순). 부서·직급은 ID만 저장되므로 이름으로 바꾸지 않고 `ID 3`으로 표시(현재 이름으로 추정 표시 금지).
- metadata `errorCount`: 파일 전체 오류(INVALID_FILE·FILE_TOO_LARGE·CONFLICT)는 1, 행 오류는 rowErrors 건수다. 라벨 "오류 수" + 캡션 "파일 전체 오류는 1건으로 기록됩니다."
- metadata가 `{}`이면 "부가 정보 없음".
- metadata는 별도 소표 `항목 | 값`. 알려진 키는 한국어 라벨(`importedCount` → 가져온 건수, `errorCount` → 오류 행 수, `rowCount` → 내보낸 행 수, `format` → 형식, `reason` → 사유, `source` → 출처, `appointmentId` → 발령 ID, `code` → 오류 코드). 모르는 키는 원래 키 이름을 mono로 그대로.
- metadata 추가 라벨: `filters` → 내보내기 조건, `reason` 값 BAD_CREDENTIALS → 아이디 또는 비밀번호 불일치, DISABLED → 비활성 계정, `source` 값 IMPORT → 엑셀 가져오기.
- 필드 키 한국어 라벨(알려진 것만): id ID, employeeNo 사번, name 이름, email 이메일, phone 전화번호, hireDate 입사일, status 재직 상태, retireDate 퇴사일, departmentId/department 부서, positionId/position 직급, role 역할, description 설명, level 정렬 순서.
- 상태·역할 값은 표시 라벨로 변환(ACTIVE→재직 등), 원래 코드값은 `title`이 아닌 괄호 없이 생략.

## 4. 상태 패턴

모든 데이터 영역은 아래 5상태를 갖는다: **로딩 / 빈 상태 / 오류 / 권한 없음 / 정상**.

### 4.1 로딩
- 영역 단위로 표시한다(페이지 전체를 가리지 않음). 패널 틀·제목·필터는 먼저 그리고, 데이터 자리만 스켈레톤(회색 막대 3~5줄, `--color-surface-subtle`, 애니메이션 없음 또는 `prefers-reduced-motion`에서 정지).
- 스크린 리더용 `role="status"` 텍스트를 함께 둔다(현행 문구 "사원 목록을 불러오는 중…" 유지).
- 300ms 미만 응답은 스켈레톤이 깜박이지 않게 지연 표시를 둬도 된다(선택).
- 재조회(필터 변경) 시에는 기존 표를 유지하고 표 위에 얇은 진행 표시 + 표 `aria-busy="true"`. 표가 사라졌다 나타나는 깜박임을 피한다.

### 4.2 빈 상태
| 상황 | 제목 | 설명 | 동작 |
|---|---|---|---|
| 검색 결과 없음 | 조건에 맞는 사원이 없습니다 | 검색어나 필터를 바꿔 보세요. | [필터 초기화] |
| 사원 0명 | 등록된 사원이 없습니다 | 사원을 직접 등록하거나 엑셀 양식으로 한 번에 가져올 수 있습니다. | [+ 사원 등록] [가져오기] |
| 발령 이력 없음 | 발령 이력이 없습니다 | 발령 기능 도입 이후의 부서·직급 변경만 기록됩니다. | (관리자) [발령 등록] |
| 대시보드 12개월 모두 0 | 최근 12개월 입사·퇴사가 없습니다 | 기준일 기준 지난 12개월 동안 기록된 입사일·퇴사일이 없습니다. | — |
| 분포 없음(재직 0) | 재직 중인 사원이 없습니다 | — | — |
| 감사 로그 결과 없음 | 조건에 맞는 기록이 없습니다 | 기간은 시작일 00:00부터 종료일 24:00 전까지입니다. | [필터 초기화] |
| 부서·직급 없음 | 등록된 부서가 없습니다 | 오른쪽 양식에서 첫 부서를 등록하세요. | — |

- 모양: 패널 안 가운데, 제목 14/600 + 설명 13 muted + 버튼. 일러스트는 넣지 않는다(필수 아님). 나중에 Codex가 작은 일러스트를 만들면 64px 이하, `alt=""`.
- "발령 이력 없음" 문구는 과거 이력을 추정 생성하지 않는다는 계약을 사용자에게 설명하는 역할을 겸한다.

### 4.3 오류
- 패널/대화상자/폼 상단 danger 알림 띠(`role="alert"`) + [다시 시도](조회 오류일 때). 문구는 서버 `message`를 우선 쓰고, 네트워크 오류는 "서버에 연결하지 못했습니다. 잠시 후 다시 시도하세요."
- 필드 오류(`fieldErrors`)는 해당 입력 아래 + 상단 요약 "입력값 3곳을 확인하세요" (링크 목록).
- 코드별 안내(계약 코드 → 화면 문구)는 9절 표를 따른다.
- 오류는 데이터를 지우지 않는다: 재조회 실패 시 직전 표를 유지하고 상단에 "최신 정보를 불러오지 못했습니다" 알림.

### 4.4 권한 없음 / 세션
- 관리자 전용 경로에 일반 사원이 접근: 셸은 유지, 본문에 neutral 패널 "이 화면은 관리자만 사용할 수 있습니다" + [내 정보로 이동]. 제목 h1 "권한이 없습니다"(현행 유지).
- 일반 사원 메뉴에는 관리자 메뉴를 **보이지 않게** 한다(비활성 표시 아님).
- 403 응답(다른 사원 이력 조회 등)은 4.3 오류 패턴 + "권한이 없습니다." 접두(현행 `ErrorNotice` 동작 유지).
- 401(만료): 로그인 화면으로 이동 + 로그인 화면 상단 info 알림 "로그인이 만료되었습니다. 다시 로그인하세요." (계약 변경 없음, 프론트 상태로만 구현 가능할 때. 불가하면 생략.)

### 4.5 진행·중복 방지
- 모든 제출 버튼은 요청 중 비활성(현행 유지). 가져오기는 업로드 중 파일 선택·제출 모두 비활성 + 진행 문구 "파일을 검사하고 등록하는 중… 창을 닫지 마세요."
- 다운로드(내보내기·양식): 버튼 라벨 `파일 만드는 중…`, 완료 후 원래 라벨. 완료 안내는 "파일을 만들었습니다"(=서버 생성 성공. "저장했습니다"라고 쓰지 않는다).

## 5. 반응형 세부

### 5.1 모바일 표 전략
| 표 | 모바일 처리 |
|---|---|
| 사원 목록 | **카드 목록**: 1행 이름(링크)+상태 배지, 2행 사번 · 부서 · 직급, 3행 입사일 |
| 발령 이력 | 카드: 1행 발령일 + 등록자, 2행 `부서 A → B`, 3행 `직급 A → B`, 4행 사유 |
| 감사 로그 | 카드: 1행 시각 + 결과 배지, 2행 행위, 3행 행위자 → 대상, [상세] |
| 가져오기 rowErrors | 표 유지(열 3개라 들어감), 사유 열 줄바꿈 허용 |
| 대시보드 수치 표·부서/직급 표 | 표 유지, 필요하면 `.table-wrap` 가로 스크롤 |

- 카드 목록도 의미 구조는 `<ul>`/`<li>`, 각 카드 안 라벨은 시각적으로 숨긴 dt/dd 또는 "사번" 같은 짧은 접두.
- 구현 부담이 크면 1차는 모든 표 `.table-wrap` 가로 스크롤 + 첫 열 고정(`position: sticky; left: 0`)으로 대체 가능. 사원 목록만은 카드 권장.

### 5.2 필터
- 데스크톱: 한 줄(검색 2fr + 선택 4개 1fr). 태블릿 2열. 모바일: 검색 1행 + [필터 (2)] 펼침 버튼(`aria-expanded`), 펼치면 선택 상자 세로 쌓기. 괄호 숫자는 적용된 필터 수.

## 6. 접근성 체크리스트 (구현·검수 공통)

1. 대비: 본문 4.5:1, 큰 글자(18.66px bold 이상)·UI 경계·포커스 링·차트 막대 3:1. 1절 토큰 사용 시 충족(설계 계산값).
2. 포커스: `:focus-visible { outline: 2px solid var(--color-focus); outline-offset: 2px; }`. 사이드바(어두운 배경) 안은 `outline-color: #ffffff`. 현행 `#96b8f5` 3px는 흰 배경 대비 약 2:1이라 교체. 포커스 링을 `outline: none`으로 지우지 않는다.
3. 키보드: 모든 동작 Tab 도달, 대화상자 포커스 가둠·Esc·복귀(현행 유지), 펼침 메뉴 `aria-expanded`, 차트는 표로 대체 가능.
4. 이름: 모든 입력에 `<label for>`, 행 버튼에 대상 이름(sr-only), 표 `<caption>`, SVG 차트 `role="img"`+`aria-label`.
5. 상태 알림: 결과 개수 변화·저장 완료는 `role="status"`, 오류는 `role="alert"`. 같은 메시지를 두 영역에서 중복 낭독하지 않는다.
6. 색 외 단서: 상태 배지 글자, 오류 "!", 감사 실패 "! 실패", 차트 범례 글자·표.
7. 확대: 200% 확대·320px 폭에서 정보 손실 없음, 가로 스크롤은 표 내부만.
8. 동작 줄이기: `prefers-reduced-motion: reduce`에서 전환·스켈레톤 애니메이션 끔. 기본 전환도 150ms 이하.
9. 언어: `<html lang="ko">` 유지, 날짜는 `YYYY-MM-DD`(계약 형식 그대로), 시각은 `YYYY-MM-DD HH:mm:ss`(서울 기준, 표 머리글에 "(KST)").
10. 사용자 입력·서버 문자열은 항상 텍스트로 렌더링(감사 로그 전후 값, 가져오기 사유, 부서 설명 포함).
