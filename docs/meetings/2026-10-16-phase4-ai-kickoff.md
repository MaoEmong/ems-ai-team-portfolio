# EMS 7단계 — AI 기능 착수 회의·계약 승인 기록

2026-10-16, . 참석: 설계 검토(Claude, 조정·결정), 백엔드·프론트·문서QA 담당(Codex). 교차 검토했다. 이 문서는 공유된 회의안·의견·승인 계약을 취합한 결정 기록이며 실제 실행 결과는 후속 QA 보고서로 구분한다.

## 의견과 결정 주체

프론트는 우선 검색·요약2기능을, 백엔드/문서QA는 기존 목록의 합성 규정Q&A까지3기능을 권장했다. 범용 급여/근태 자유질의는 제외하고 기존 권한·공개규칙을 유지하는 데 의견이 일치했다. 검색 제안을 사용자 확인 후 기존 목록에 적용하고 평가 요약은 읽기 전용으로 하는 안을 제안했다. 문서QA는 인용 검증의 의미적 한계와 Mock/실호출 증거 구분을 강조했다.

설계 검토에서는 [AI 계약 승인] 메시지로 [phase4-ai-api.md v1.0](../api/phase4-ai-api.md), SHA-256 `E117946FE967747697A8AD6A3D0AF9A729991DB1A547BB6A468D7B09601A5617`을 승인했다. 아래 세부 정책의 결정자는 Claude Code가며 사용자가 각각 선택했다고 기록하지 않는다. API는 7단계 회의 및 를 근거로 명시한다.

## 승인된 범위·조정

1. Mock/Anthropic/Ollama 제공자 추상화와3기능(검색 필터 제안·확정 평가 코멘트 요약·합성 규정Q&A)을 다룬다. 개발 AI엔진과 제품 제공자는 구분한다.
2. AI-01은 기존 목록의 keyword/departmentId/positionId/status/sort **5필드만** 지원한다. 직책·입사일 범위는 UNSUPPORTED/빈필터로 안내하고 기존 GET /employees를 확장하지 않는다. hireDate 정렬과 날짜 범위 지원을 혼동하지 않는다. 서버는 검색을 실행하지 않고 사용자 적용 후 기존 API가 권한을 다시 검사한다.
3. AI-02는 FINALIZED의 본인/배정 평가자만, 타인/다른ADMIN404·미확정409·사전 거절 시 제공자 호출0회다. 평가 항목/코멘트만 보내고 ID·점수·등급은 제외하며 원문을 저장/수정하지 않는다.
4. AI-03은 고정 합성 규정의 인용ID/버전/절·발췌 원문을 검증한다. 근거 불일치면 모델 답변 미노출·INSUFFICIENT_EVIDENCE다. 인용 일치가 의미적 정확성 보장은 아니다.
5. 비스트리밍·자동 재시도0·공유캐시없음·Mock 자동 대체없음, 키 없는 기본 Mock 데모를 적용한다. 제공자 실패·시간초과·JSON 오류·한도를 계약대로 구분한다. 모델 기본 설정과 실제 접근/성공은 별도로 기록한다.
6. 원문/키/전체 프롬프트/응답 대신 AI_INVOKE의 허용 메타데이터만 감사한다. 업무 테이블·결과 저장은 추가하지 않으며 스키마 변경 없으면 새 마이그레이션도 불필요하다.

상한·오류·상태별 인수 기대값은 [공통 정책표](../phase4-ai-policy.md)와 [요구사항](../01-requirements.md)에 대조했다. 초기 로드맵의 AI-01~04 번호는 승인 API의3기능과 AI-CFG-01 대응표로 정리한다.

## 역할·착수 조건

- 백엔드 Codex: LlmClient/어댑터·상세API·테스트·Compose와 백엔드 ADR/일지. 프론트 Codex: API연동·화면·목업/테스트, Claude Code(디자인): 시안·실제 이미지 검수/재확인. 3B 시안523행 공백도 프론트가 정리한다.
- 문서QA Codex: 당시에는 공통 문서 초안만 작성했다. 실제 Compose·스크린샷·커밋은 양 팀 최종 인계를 설계 검토에서 검증하고 별도 인계 확인을 마친 뒤 진행한다. 계약 승인은 QA 착수 통지가 아니다.
- Mock 단위/MySQL·로컬HTTP계약·실제Claude/Ollama·Chromium·Claude 디자인 검수는 서로 대체하지 않는다. 키/서비스가 없으면 실호출 미실행으로 기록한다.
- 검증 결과와 결함은 실제 근거와 함께 기록하고 완료 여부는 산출물로 확인한다.
