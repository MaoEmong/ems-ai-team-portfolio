다른 팀의 2차 발언 전문은 이 작업에 전달되지 않았으므로 추정해 기록하지 않습니다. 최종 쟁점은 아래 의장 결정으로 확정되었습니다.

## 범위 결정

1. MVP: 사원·부서·직급 CRUD, 사원 검색·필터·정렬·페이징, JWT 로그인과 ADMIN/EMPLOYEE 권한.
2. 확장 1: 대시보드, 부서 이동·승진 이력, xlsx 기본 입출력 및 CSV 내보내기, 감사 로그.
3. 확장 2: 근태, 휴가 신청·승인/반려·잔여 연차, 급여, 평가, 조직도·직책, 알림. MVP는 직급만 관리.
4. AI: Claude API/Ollama 공통 인터페이스, 자연어 사원 검색, 평가 코멘트 요약, HR 규정 챗봇.

이번 작업 분담은 초기 세팅·MVP까지. 2~4단계는 단계 종료 회의 후 별도 작업 분담합니다. 배포는 하지 않습니다.

## 쟁점 결정

- 삭제는 퇴사 처리(논리 삭제)이며 물리 삭제 API 없음. 버튼은 '퇴사 처리', RETIRED·퇴사일 기록·계정 비활성화. 기존 JWT도 매 요청 계정 상태 검사로 401. 사번 재사용 금지. 기본 목록 RETIRED 제외, status로 조회 가능.
- 부서·직급 관리 CRUD 화면을 MVP에 포함. 퇴사자 포함 소속 사원이 있으면 삭제 409.
- EMPLOYEE는 본인 조회만, 본인 수정도 금지. 서버에서 강제. 부서·직급 목록은 인증 사용자에게 허용.
- Access token 1개, 1시간, refresh 없음. sessionStorage 보관, 401 로그인 이동. 로그아웃은 클라이언트 토큰 삭제. 백엔드가 근거·한계 ADR 작성.
- Flyway 도입. 환경변수 비밀번호를 사용하는 관리자 1개와 합성 사원 약 30명 시드.
- 단위/슬라이스 테스트 및 MySQL 통합 테스트(Testcontainers 또는 Compose). H2만으로 통합 완료 판정 금지. 미실행은 명시.

## API 결정

`/api/v1`, JSON, Bearer 인증. 날짜 YYYY-MM-DD, 시각 오프셋 포함 ISO-8601/Asia/Seoul. 페이지는 0부터, size 기본 20·최대 100, employeeNo/name/hireDate 정렬. 공통 페이지·오류 구조, 인증·사원·부서·직급 경로와 필드는 [계약 요약](../02-architecture.md)에 정리합니다. 상세판 `docs/api/mvp-api.md`는 백엔드 담당입니다. 변경은 설계 검토 확인 후 양 팀에 공유합니다.

## 소유권 및 진행 순서

| 담당 | 소유 범위 |
| --- | --- |
| 문서QA | 루트 초기 세팅, README, .gitignore, .env.example 취합, 공통 docs, 색인, Git 커밋 |
| 백엔드 | backend/, docker-compose.yml 단일 편집, 상세 API, 백엔드 ADR |
| 프론트 | frontend/ 및 Dockerfile, 프론트 ADR; Compose 요구는 백엔드에 전달 |
| 각 팀 | 고유 이름의 개발일지 및 담당 ADR |

ADR 대역: 문서QA 0001~0099, 백엔드 0100~0199, 프론트 0200~0299. 추가 대역은 조율합니다. 개발일지 `YYYYMMDD-<팀>-<작업>.md`. 포트 MySQL 3306/backend 8080/frontend 5173, CORS `http://localhost:5173`.

문서QA 초기 세팅 → 백엔드·프론트 계약 기준 병행 → 설계 검토에서 통합 검수·커밋 별도 작업 분담 → 1단계 종료 회의.

기록은 지시→수행→채택/수정/기각 근거→문제와 해결→검증 결과로 남깁니다. AI 판단을 사람 판단으로 표현하지 않으며 개발 AI와 제품 LLM을 구분합니다. 비밀값·토큰·실존 개인정보 기록 금지.
