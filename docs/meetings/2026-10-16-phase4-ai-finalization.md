# EMS 8~10단계 — AI 최종화·검수·커밋

결정자: Claude Code(설계 검토). 사용자 개별 승인으로 표현하지 않는다. 8단계는 백엔드·프론트·문서QA(Codex), 9단계는 백엔드·문서QA, 10단계는 문서QA가 두 차례씩 의견을 제출했다. 완료된 다른 팀은 결함 수정이 필요할 때만 참여한다.

## 8단계 결정과 미완료 이력

- 승인 API v1.0 및 7단계 후속 결정 유지. AI-01은 기존5필드, 직책/입사일 범위UNSUPPORTED다. C01은 비교표·명시 적용·5필드 전체 교체, 미제안 조건 제거·수동 수정·되돌리기를 지원한다.
- 프론트 bridge는404만null, 응답 없음/기타상태/JSON실패는throw다. TS2322와269/270 중간 실패를 보존하고 최종 수정 후 한 번의 전체 실행으로 수치를 갱신한다. 회의 훅에 막힌 패치는 미반영으로 적고 실행 단계에서 처리한다.
- .env.example AI변수10개는 백엔드 승인 작업이며 반복 구현하지 않는다. 프론트 최종 완료→설계 검토 확인→백엔드 전체3서비스 실행/종료→설계 검토 확인→QA 순서다.

## 9단계 결정과 인계

- 백엔드 실행 배정은 [프론트 완료 통지]였으며 QA 착수와 구분했다. 백엔드는21:01:36~21:04:49 KST에3서비스를 빌드·기동해frontend200·Mock3기능/CORS·보존/새DB·down을 확인했다.
- backend-only(19:50~19:54), 전체3서비스, QA직접 실행은 각각 명령·시각·서비스·manifest·이미지·DB프로젝트로 분리한다. 141/73과276/10을 QA 직접 재실행 결과로 쓰지 않는다.
- 스키마 변경이 없어V4를 유지하며 V5/업그레이드라고 쓰지 않는다. 기존 데이터는 삭제하지 않고 기준값·증감으로 검사한다.

## 10단계 결정과 실제 착수

검증 작업 실행 배정 자체가 **통합 검수 시작**다. QA는 별도 통지를 다시 요청하지 않고 인계 확인→mysql만 기동/사전 스냅샷→전체기동/보존→기존62회귀→AI/C01→별도빈DB→양쪽down/볼륨유지→문서→3개커밋 순서로 진행한다.

정상Mock의 잘못된 출력/ID·지연·AI_BUSY·호출0회·전송캡처 재현불가는 승인 [백엔드 인계표](../../backend/verification/20261016-phase4-qa-handoff.md)의 테스트명·시각에 연결하고 QA직접미실행으로 적는다. 입력400과출력502,감사0건과제공자진입0회를 구분한다. 실Claude/Ollama추론은 키/기존서비스 미구성으로 미실행이며 키탐색·모델다운로드·제품 테스트옵션을 추가하지 않는다.

검사 실패는 제품/QA오류를 재현 근거로 구분하고 최초 결과를 보존한다. 제품 결함은 심각도·재현·담당팀을 검토 기록로 보고하고 타팀코드를 수정하지 않는다. 소스/이미지가 바뀌면 영향 검증을 갱신한다.

## 완료와 전체 목표 판정

공통 문서·제공자별 실행표·보고서/스크립트/JSON/스크린샷과 전체 목표 대조표를 제출한다. 신규파일포함staged diff·실제키/산출물검사를 통과한 작업주체본문3커밋,해시/clean·down/볼륨유지를 확인한다. 기존이력은amend/rebase하지 않는다. 중간은검토 기록,완료 기록1회이며 거절되면 동일내용검토 기록로 인계한다. 최종 완료 검토와 그룹1~3+승인AI 충족판정은 설계 검토에서 한다.
