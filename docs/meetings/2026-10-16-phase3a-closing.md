## 조기 완료 사건과 대응

이전 에서 백엔드·프론트 중간 완료 기록이 완료로 처리되어 검증 작업가 실제 완료 전에 종료 표시됐고 검토 단계에서 실행·작업 분담이 차단됐다. QA는 실제 일지·디자인 기록 부재를 확인해 착수하지 않았다. 사용자의 진행 질문으로 새 에서 마무리 범위를 재확정했다.

재개 후에도 프론트 검증 작업의 중간 메시지가 done으로 표시되는 두 번째 사례가 발생했다. 설계 검토에서는  답변에서 백엔드93/28 PASS·Compose/down 완료, 프론트95/95·빌드 PASS이나 Chromium 진단·Claude 검수 미완료라고 확인했다. QA는 독립적인 문서·스크립트 준비만 허용받았다. 실제 Compose 검수·README 스크린샷·커밋은 설계 검토의 최종 인계까지 보류한다.

## 재발 방지·진행

완료 기록은 모든 완료 기준 충족 후 한 번만, 중간 상황·질문·결함은 검토 기록로 보낸다. 진행 상태 표시을 증거로 쓰지 않는다. 명령·시각·최종 소스 결과·미실행·결함·문서 경로를 인계하며 다른 시점 결과를 합산하지 않는다. ACL/훅 차단은 반복·우회하지 않고 보고한다.

백엔드/프론트 병행 후 실제 완료와 Claude 기록을 설계 검토에서 확인해 QA에 인계한다. 공유 Compose는 담당 팀 사용 후 down·볼륨 유지한다. QA 검수·커밋 이후 설계 검토에서 완료 검토를 판단하고 3B 회의로 이어간다. 최신 최종 결과는 실제 인계 후 추가한다.
