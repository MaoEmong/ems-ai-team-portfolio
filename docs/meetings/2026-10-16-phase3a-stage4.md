# 3A 4단계 설계 검토: QA 통합 검수·문서·커밋


인계 확인: design-review-phase3a §7.2/7.5/8, 프론트최종97/97·Chromium6/6·24장, ADR0204·일지. QA직접 실행과 각 팀 과거 근거를 주체/시각별로 구분한다.

유지DB 시작 행수/기준집계를 저장하고 고유 합성 데이터로 검수한다. 이미V3이므로 보존/재시드없음만 직접 확인하며 V2→V3는 백엔드 체크섬에 연결한다. 새DB는 별도 빈볼륨에서31/31/퇴사5/기본26/DEMO001·분산차트를 확인한다.

기존34개 및 근태/휴가/알림, 미래정정 서버거절·오류필드·불변, 기존사원API 식별 표시, 미기록 표시를 실제Compose/MySQL/Chromium으로 확인한다. 시계경계 미재현은 Clock/MySQL과 브라우저 미실행을 구분한다. 결함은 담당/재현/심각도와 함께 검토 기록으로 보고하고 다른 팀 코드는 수정하지 않는다.

문서는 착수/마무리/2·3·4단계·요구사항·ERD·API·README·회고·색인·AI협업 기록·일지를 최종화한다. 1~4차 검토의 인계·실행 근거를 확인하고 미확인 원인은 단정하지 않는다. 검토 중 보류된 실행과 환경 장애를 구분한다. 낮음디자인7건 수용·ExcelJS경고·프론트EOF빈줄3건은 잔여로 유지한다.

종료는 down·볼륨유지, 비밀값/산출물 검사, 명령단위safe.directory를 사용한 백엔드/프론트디자인/문서QA3커밋과Git상태 보고다. 검증 결과와 결함은 실제 근거와 함께 기록하고 완료 여부는 산출물로 확인한다.
